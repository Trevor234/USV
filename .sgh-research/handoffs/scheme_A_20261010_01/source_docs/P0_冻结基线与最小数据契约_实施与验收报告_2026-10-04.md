## 3. 最小合同 v1 的实际实现

schema：`p0-contract-v1`。每条研究消息绑定 run、producer instance、baseline、config hash、从 1 开始的独立序号、clock epoch、显式仿真时刻和 boot 对应的 steady 时钟域。重复恒值输出也形成新事件。

| 已部署消息/话题 | 实际语义 |
|---|---|
| `StateSnapshot` / `/research/state_snapshot` | 同一条 ground-truth odom 的 `[x,y,psi,u,v,r]`，保留原 header、接收/冻结 steady、frame/child_frame、clock 年龄、有效性和质量原因；body twist 不再旋转 |
| `CycleTiming` / `/research/cycle_timing` | 记录回调、复制、参考、完整 solve、后端和发布时序；保留实际 solve 输入和 odom/IMU 接收身份。IMU 覆盖 r 时明确 `controller_mixed`，不冒充同源 odom |
| `AppliedControl` / `/research/control/applied` | `event_semantics=publisher_command`；左右请求/最终 N、原控制来源、映射与限制、上一发布锚点、两路调用起止及成功/异常、分别观察到的 clock/epoch/年龄 |

研究 logger 使用容量 1024 的有界异步队列。控制回调只入队，独立线程发研究消息并写摘要，不增加物理推力发布者。生成、发出、丢弃、首末序号均计数；溢出、异常关机、未刷新、部分发布或 interrupted cycle 使录制完整性失败。

研究记录默认关闭。研究入口固定动态 B，原 recorder 关闭，只启一个 MCAP recorder；graph 门禁通过后才 armed。源摘要位于 bag 外 `source/session_summary.json`，保存真实窗口开始/结束及计数。原始 odom/IMU/clock/path/profile、左右推力、status、预测轨迹与三研究话题共 12 条录制。

正常停止先向本次隔离域中唯一的控制节点发 SIGINT，在有效 rclcpp context 的 pre-shutdown 回调内执行原零输出并刷新研究队列；摘要存在后保留 recorder 尾部时间，再停止本次 launch。只终止本轮所属进程组，不把全机 ROS/Gazebo 作为清理对象。[Jazzy rclcpp Context 实现](https://github.com/ros2/rclcpp/blob/jazzy/rclcpp/src/rclcpp/context.cpp)给出了 pre-shutdown 与底层 context 关闭的先后关系。

## 4. 三种时间和 frame 证据

| 时间 | 本次用途 |
|---|---|
| bag system receive 时间 | 联合事件与左右原始 Float64 的严格唯一匹配；预先冻结 20 ms 窗口，不能按数值相同挑配对 |
| 显式 `/clock` + epoch | 发布命令区间的仿真时间边界，保留暂停/回退/跳变/年龄；不拿墙钟替代 |
| 同机同 boot 的 steady 时间 | 完整 solve、回调到发布调用的本地链路、左右差值及墙钟发布间隔 |

本次 recorder 使用默认 system receive，不启用 `--use-sim-time`。MPC 的 `use_sim_time=true` 另由实际参数核验。窗口内两路推力逐事件唯一匹配，三 run 最大 bag 接收偏差均不足 0.242 ms，显著低于预先固定的 20 ms 门槛；这仍是接收/记录对拍，不是 plant 接收延迟。

实际生成 SDF 的 OdometryPublisher 为 dimensions=3、`map` / `wamv/base_link`，实际 raw odom 的 frame 一致。Gazebo 8 插件对世界速度做逆姿态旋转后发布船体 twist，Jazzy bridge 复制相应字段，因此快照不重复旋转。[Gazebo 8 OdometryPublisher 原实现](https://github.com/gazebosim/gz-sim/blob/gz-sim8/src/systems/odometry_publisher/OdometryPublisher.cc)、[Jazzy ros_gz odometry 转换](https://github.com/gazebosim/ros_gz/blob/jazzy/ros_gz_bridge/src/convert/nav_msgs.cpp)。插件 twist 还使用 rolling mean；它不能未经滤波时序分析就当瞬时动力学真值。

三 run 的 effective vehicle 字节相同，运行 MPC 的 vehicle 参数与各自 effective vehicle 一致。SDF 的精确哈希分别保留；仅替换各实验 mesh 输出目录后文本一致，model report 差异也仅为 SDF 路径。plant 仍由相同 launch 模型生成，**这不证明 plant 与控制器离散动力学已独立对拍或解耦。**
