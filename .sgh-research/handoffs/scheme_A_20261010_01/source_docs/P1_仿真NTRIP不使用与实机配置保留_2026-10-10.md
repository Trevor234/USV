# 仿真中不使用 NTRIP，实机配置保留

日期：2026-10-10。根据用户确认，NTRIP/CORS 差分服务只用于实机，本阶段仿真无需配置、连接或验收该服务。

## 实施结果

当前代码已经符合这个要求，因此本次没有修改远端 launch、配置、relay、setup 或 package 文件，也没有构建或启动/停止节点。这里的“不使用”是仿真启动图不加载该功能，不是清空参数、删除配置或全局禁用实机服务。

| 入口 | 现有行为 | 本阶段处理 |
|---|---|---|
| sim.launch.py | Include vrx.launch.py | 不加载 NTRIP 客户端和 fix_qos_relay |
| vrx.launch.py | 启动 VRX、控制器、planner、visualizer 和可选 bag | 不读取 NTRIP 参数，不要求 CORS 连接 |
| sitl.launch.py | 启动 MAVROS、控制器、planner、safety 和可选 visualizer | 不加载 NTRIP 子图 |
| 两份 P0 recording launch | recorder + Include vrx | 不添加 NTRIP 依赖 |
| real.launch.py | use_ntrip 默认 true，IfCondition 控制 ntrip Include | 保留实机原行为；需要关闭时仍可 use_ntrip:=false |
| ntrip.launch.py | 手动实机入口，启动客户端和中继 | 完整保留，未来实机按需配置和验证 |

仿真入口没有 use_ntrip 的读取或控制分支，不需要新增一个仿真开关。实机与 standalone 入口也没有被全局禁用；在仿真主机上单独手动启动实机入口仍是另一项操作，不属于上述仿真入口的行为。本次没有查询或终止主机上已有的运行进程。

## 检查依据与边界

读取了9份 bringup launch 的完整内容，以及安装目录的实际解析目标和 SHA。sim、vrx、sitl 和两份 P0 recording 入口都没有 NTRIP Node、Include、配置读取或 relay 动作。

补查了 vrx_spawn.py：source/build 的解析目标和内容一致，返回 Gazebo simulation、船体 spawn、话题 bridge、robot_state_publisher 等动作。外部 vrx_gz.launch.simulation 的实际安装模块也已读取，返回 ros_gz_sim/gz_sim.launch.py、monitor_sim.py 与退出事件处理，没有 NTRIP 加载。这里是代码与解析路径的静态审阅，不是运行时进程或网络流量测试；未启动 Gazebo、MAVROS 或控制器。

全部 launch 和 config 的读取前后 SHA 一致。ntrip_params.yaml 的连接/认证内容未打印或重写；relay、setup 和 package 的身份另有记录。

原编号10/18的 ntrip_params.yaml、14/22的 ntrip.launch.py：仍属于旧环境清单中的真实内容变化，但它们不被本阶段所审阅仿真入口读取，不作为当前仿真功能故障或 NTRIP 集成阻塞项。未来实机启用时再配置并验证连接、QoS、GGA、RTCM 与故障行为。

GPS 原始话题记录与 NTRIP 服务不是同一功能。此次没有删除 GPS 话题、QoS 或录制配置；HOLD 故障策略、NMPC/PPO 以及其他差异的适用性不因这项说明自动改变。

保留原3864清单和原差异记录；本次没有重跑、替换或放宽该 guard。上次整体 guard=false 的证据仍保留，D1 未放行。本说明不能单独解除其他验收条件；后续仿真检查应按真实启动依赖建立明确的范围和清单，不以忽略旧路径变化伪造完整环境一致性。
