## 1. 问题前提与实际并发路径

F4 的正常仿真未出现异常参考记录，但这不能排除资格检查和输入冻结之间的竞态。现场源码的 I/O callback group 为 Reentrant，control group 为独立 MutuallyExclusive，主程序使用 3 线程 MultiThreadedExecutor。旧 `control_loop_()` 在 `state_lock_` 内检查 `can_solve_()`，随后释放锁；`run_dynamic_mpc_()` 再次获取状态锁复制状态和建立 reference，未在这次临界区重新检查资格。合法路径因此可能在两次取锁之间被真实 callback 清空或改成单点。

本轮把它归为**资格判断与输入读取时刻不一致**，不是动力学模型误差或速度跟踪偏差的根因。正常仿真用于验证兼容和记录合同，确定性节点测试用于覆盖该交错；两类证据分别报告。

## 2. 最小生产修复与保证边界

只修改动态 B 的 `run_dynamic_mpc_()` 最后一个输入临界区：

1. 获取同一 `state_lock_`，立即复核原 `can_solve_()`。
2. 不合格时先释放状态锁，再调用原 standby 路径，并在已启用记录时填写拒绝原因；不建立参考、不调用 solve。
3. 合格时持续持有同一把锁，复制当前状态、来源身份及 path/profile 元数据，并建立该次实际 reference。释放锁后才执行同步 solver。

提前解锁再 standby 是必要的：standby 会获取 output lock，后续状态更新又涉及 state lock；不能新增反向嵌套锁序。输入锁不跨 native solve 持有。

本次保证的是**资格复核与该次 state/reference 冻结处于一个临界区**。冻结期间 callback 排队，冻结后到达的新输入由后续周期使用。它不保证冻结状态永远不过龄，也不使已开始的 native solve 可抢占。

**冻结后 clear 的现状已明确测试：当前同步候选仍可按既有 deadline 规则完成并发布，下一次实际 `control_loop_` 回调调用因 no_path 待机。** 本次未把 clear 定义为在途任务取消；未来 P1 必须另行规定任务 generation、发布决策提交边界和失效策略。这里的输入原子冻结也不意味着左右推力同时被 plant 接受。

保留原 outer precheck、solver 模型和代价、reference 数值函数、fallback、推力映射、deadline 及日志 schema。未修改 header、消息接口、配置来源、合同检查器、PPO 或运动学 A。

## 7. 下一工作包：独立 worker、固定执行 tick 与唯一发布责任

本轮复盘使用 [control-postrun-retro](C:/Users/sgh/.agents/skills/control-postrun-retro/SKILL.md) 的完整性、机制、下一步和停止条件流程，EDA/Slurm 专属产物不适用，改用 USV baseline、ROS 合同及计时证据。机制判断为资格/读取时刻不一致；本工作包已关闭该缺口，下一项依赖是同步 solver 与输出调度分离。

建议先锁定下面的最小架构与验收合同，再实施：

1. **单 worker 独占 solver。** freeze 只建立不可变 job；solve、热启动及 `set_applied_control` 由该 worker 顺序处理。tick 不并发调用同一 backend。交接有界：一个 active、可替换 pending 和 ready 槽，不因 timeout 增生线程。
2. **固定 steady tick 独立决策。** tick 不等待 solver，记录 queue wait、solve、ready、decision、publish 各阶段。用完整候选年龄、shape/finite、版本、来源年龄、epoch 和 consumed ID 决定接纳，不能只信 backend 报时。周期、TTL、fallback 和 jitter/max gap 门槛在新试验前冻结。
3. **明确任务失效边界。** 推荐 clear/任务替换在发布决策提交前使旧 job 失去资格；native solve 可继续完成后丢弃。区分 task generation 与普通 state/profile 接收 sequence，避免高频正常更新使所有解无条件过期。提交后的动作只能由同一出口接替，不宣称撤回已被 plant 接受的动作。
4. **唯一输出责任。** 正常候选、fallback、standby、HOLD 和 shutdown 均串行仲裁；worker 与 callback 不直接发布。最终变化限制用实际 mapped publisher anchor 与真实 steady 间隔，零/释放/关机例外提前说明。唯一 publisher 仍不是左右物理同时执行证明。

最小验收覆盖正常 logging off/on、50/150/250/400 ms fake solve 和受控阻塞、坏 shape/NaN、失败/连续五 tick 无新解、重复/旧/乱序 candidate、状态过龄、clear/任务/模型/配置版本更新、sim reset、shutdown 的提交前后交错。先通过可控屏障证明 solver 未释放时多个独立 tick 仍决策发布，再用真实新 baseline 的正常与故障 run 检查预冻结时序门槛。旧 `CycleTiming` 的同步 timer/solve 含义发生变化时需版本化，不能让旧 checker 对新异步语义假通过。
