## 1. 原问题与本轮范围

旧 v13 regulator 的 execute 门要求 `execute_qualified=true` 且 `parameters_are_diagnostic_only=false`，后面的能力租约门却无条件要求诊断 flag 为 true 及 diag5，两者互斥。简单翻转两个 flag 无法获得一致的正式加载路径；只检查文件 hash 也无法发现缺字段、错类型、错误模型或政策。

本轮建立一个受控的参数规格与两个独立实现。模型、时间、幅值、映射、权重、十九个水动力参数及政策锁定到当前已登记候选组合 `F5_P1_candidate_20261007_01`；资源字段沿用既有支持范围。改变固定组合须增加受控 profile/版本、补来源并重验受影响路径。这个支持域决定代码可接受哪些参数，不表示参数已经完成校准。

## 2. 实现后的合同与角色

| 对象 | 字段与状态 | 纯模式检查 | 真实物理启动 |
|---|---|---|---|
| 旧 v2 diag5 | 原 74 字段；诊断、execute=false、原 fault 策略 | no_output/shadow 允许，execute 拒绝 | 拒绝 |
| 新 v3 预冻结 | 77 字段；`qualification=execution_pre_freeze`；execute=false；diagnostic_only=true；fault=false；保留八项待校准；冻结 hash 为空 | 仅 no_output 允许 | 拒绝 |
| v3 frozen 结构测试夹具 | 执行/资源 revision 各 1；profile 固定；frozen flag/pending/hash 结构一致 | 可验证 no_output/execute 的结构 | **本轮实际 regulator 仍拒绝 execute** |

新 schema 是 `p1-execution-contract-v3`。删除旧 `diagnostic_contract_revision`，增加 `execution_contract_revision`、`resource_contract_revision`、`supported_parameter_profile`、`freeze_evidence_sha256`。pre 的 diagnostic_only=true 是本轮明确选定的语义：参数仍待来源冻结，即使 schema 已具备正式字段。结构 frozen 对象只存在于测试夹具，不是资格文件；伪造一个 64 位 hash 和 true flag 不会开放入口。

C++ 编译常量 `physical_execute_release_enabled=false`；Python 实际运行门也保持关闭。regulator 先加载完整合同并验证 runtime 模式，再检查 worker 身份、构建 Sink/source 和业务/物理 publisher。worker 没有 execute mode；它在 source/native backend/publisher 前验证完整字段和资源，不能将其描述为通过了 regulator 的物理模式门。基类 Node 已可能短暂出现在 DDS 图中，拒绝门不承诺零 ROS 初始化。

正式合同禁止非零故障注入。节点和 runner 默认 0 保持正常路径；本轮没有将显式传入 0 的 override 另定义为故障许可。

## 3. 完整校验规则

- 必需字段逐项检查，拒绝未知字段、缺失字段、混合版本和错误资格组合；嵌套 hydro/topics、数组维度、元素类型也检查。
- revision、N、ns 时间、capacity、depth 和 byte budget 要求 JSON 真整数，拒绝 bool、浮点整数、字符串以及有符号 int64 溢出。
- 数值必须有限；原始 JSON 拒绝 NaN、Infinity、1e309、非法编码和重复 key，包含相同值的顶层/嵌套重复键。合同读取上限为 64 KiB，等号允许、超过拒绝。
- 固定模型和参数逐值匹配；policy/topic/frame/nominal/profile 逐项匹配当前支持值。资源边界复用原已验证实现，并采用独立 formal resource revision。
- 较小正 history/log capacity 在原实现范围内可加载，不证明其历史覆盖或证据容量足够；来源和实际选择仍属于 B4/B5。

旧 Python 历史 recognizer、诊断 runner、VRX runner及 v2 checker 分支保留；新 formal 无输出入口使用完整 validator。生产 C++ diag5 同样新增完整类型、finite 和字段拒绝，是明确的拒绝增强，不能声称所有旧错误输入行为完全不变。
