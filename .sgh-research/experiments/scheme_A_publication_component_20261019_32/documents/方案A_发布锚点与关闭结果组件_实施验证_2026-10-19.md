# 方案A第32批：发布结果、每侧锚点与关闭结果组件

日期：2026-10-19。本批在隔离的新派生源码中落实第31批的最小组件工作包，没有启动ROS节点、控制闭环或M4接管。

## 1. 改了什么，起什么作用

原regulator的publish方法内联了两侧API调用、结果、锚点更新、span/gap/rate检查；shadow模式直接返回，旧正常run没有执行这段代码。既有CommandAnchor是外部命令观察/事务组件，未替代节点自己的发布结果路径。

新增 `author/observer/src/shadow/publication_result_v1.hpp`，提供无ROS依赖的publish_pair、apply_channel_result和shutdown_result；新派生regulator的原publish与finish_tick改为调用这些共享函数。运行节点与组件测试使用同一实现，避免测试另一套“等价”副本。CMake只构建新节点和一个纯C++测试目标；旧无关测试不重复运行，也不累加为本批通过数。

保持原顺序与政策：每侧实际API start作为自身锚点时间，正常返回才增加成功序号并写持有/发布历史；失败侧仅失去known，保留旧数值作为不可授权的历史。左侧失败后仍按原策略尝试右侧，已经返回成功的调用不能撤回。历史写入与失效操作仍由regulator原业务锁保护，锁不跨ROS publish。

span、每侧gap/rate预算按原值及严格/含等号规则计算；这些是API返回后的观察，不会撤销已经发生的发布。原p1_admission.hpp中的hold/fallback和原完整合同、协议逐字节未改。source审查确认除了共享头include、publish函数和shutdown结果投影，没有其余regulator改动。

关闭继续保留原有限策略：请求近零可以结束本拍；双侧近零命令API均返回成功才另记zero_target_published。达到关闭grace也可在非零请求下退出，记录grace而不声称发布零成功。它们均不证明plant收到、实测推力或船体停止。

## 2. 必要验证及具体结果

首次构建即通过，无修正重建。新节点与纯C++测试两个目标均编译成功；Native事件表14组、117断言通过，构建/验证及输入锁采集共73.670秒，低于事前120秒预算。无install或codegen。

| 事件 | 验证结果及意义 |
|---|---|
| 双侧正常返回 | 左commit先于右begin；各侧独立序号与实际start时间准确，不能用API end或计划tick作锚点。 |
| 左成功右失败／左失败右仍调用／双失败 | 失败侧unknown、不增加成功序号；另一侧成功不能回滚，只有成功侧产生历史。未知侧后续请求零，已知侧按真实锚点斜坡。 |
| 每侧不同实际间隔 | 左侧200ms允许16N变化，右侧约100ms不允许同一16N变化，能识别误用统一200ms的问题；超界是返回后事实。 |
| 5ms span与240ms gap | 等号在原预算内，增加1ns则超界；span失败与rho_available是原有不同诊断事实，未混成同一安全承诺。 |
| 先前锚点未知，当前调用成功 | 当前侧可以重新known，但不能据此补造先前区间的率限依据。 |
| hold600ms及连续五拍缺候选 | 重发不刷新last_accepted；前3拍持有，第四拍约25→9N，第五拍约9→0N，每步合法。第五拍零是按率限自然到达，未使用硬编码“第五拍归零”。 |
| 来源失效 | 即使仍在hold时间内也立即走已知锚点斜坡，不额外等待600ms。 |
| 关闭近零／单侧失败／grace／shadow | 请求近零允许退出与双侧成功近零发布分账；shadow不能产生成功零发布事实，非零grace退出不冒称零推力。 |

这些send结果是测试注入的局部回调事件，不是DDS物理话题发布。Native没有ROS头依赖，动态链接也没有rcl/rclcpp/rmw；未创建ROS context或任何执行器端点。新runtime ELF完成编译及共享代码接入检查，但其publish分支没有被实际执行。V4获得的是组件前提，尚不是M4或实际发布链资格。
