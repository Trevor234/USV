# 第23批离线启动机制：输入、方法和结论边界

日期：2026-10-18。父批为第22批 `scheme_A_reference_pair_wakeup_20261018_22`。本批承接父批下一步计划的时序分解、实际后端复现、固定输入重复 RTI 三项工作。

## 1. 为什么要加不移位对照

实际 `AcadosBackend::solve()` 成功后会把状态、控制热启动轨迹向前移一个节点，并更新内部 `u_prev_`。因此反复调用公开接口，即使外部状态与参考保持不变，也同时引入了热启动移位。

本批并列三组：公开后端接口；调用同一已安装代码生成库、实现相同移位策略的 C API；同一 C API 在当前 Job 的重复期间保持未移位的上一解。两组 C API 均按实际顺序完整执行选定 Job 之前的前缀，前缀仍使用原移位规则。每次调用前显式重新设置实际 anchor。首个选定调用遵循实际 `reset_warmstart`，后续重复不重置。

这仅改变离线求解器的初值更新方式。它没有建立新的运行期初始化策略，也没有把重复求解部署到闭环。C API 实现依据冻结的可读后端源码；与实际二进制行为的一致性，必须由实际 102 个 Job 的首控及全部 X/U 数值对照另外证明。源码可读、归档散列正确，不能单独建立历史编译来源的证明。

## 2. 固定数据与预先登记

主分析是实际 Job 1；Job 2、5、10 为诊断。每个选定 Job 固定重复 12 次，禁止按结果扩大次数或挑选更好的初态。数据取自父批实际 Worker 的 102 个候选记录，完整保留 Job、预期首控、126 个状态预测值和40个控制预测值。独立审计重新逐项绑定原 Worker JSONL。

每次重复固定状态、anchor、参考、N=20、dt=0.2 s、全部水动力参数、Q=[20,20,50,8,1,8]、R=[0.05,0.05]、Rd=[0.2,0.2]、Qf_scale=8、输入 ±25 N、后端变化率 80 N/s。实际启动 Job 的状态和 anchor 为零，参考速度为0.05 m/s。实际 `reset_warmstart=false` 由新建后端的冷状态承接，不能改写成另一次人为 reset。

登记文件为 `preregister/selected_solver_scope_v1.json`，早于变体数据生成。主 Job 的“几乎不变”同时要求：相对于第1次，所有重复中的最大首控变化 ≤0.0001 N、相对变化 ≤0.001、非线性可行 rollout 代价相对变化 ≤0.001。采用所有重复的最大变化，不只比较第1次和最后一次。

## 3. 必须先通过的数值校验

使用实际 Worker 链接的三个已安装静态库构建新的离线程序。构建前记录源文件、外部输入、编译工具、实际 Worker ELF 和链接命令；生成新 ELF 后、任何原生测试求解前记录解析后的动态加载库。实验调用前后再次核对源码、静态库、动态库及770项编译依赖。

公开接口和同移位 C API 都要先按完整顺序复现实际102个 Job。首控容差为1e-10 N，完整状态/控制预测容差为1e-9；固定输入重复时，公开接口与同移位 C API 的首控和完整预测差异均不得超过1e-10。它们通过后，才解释不移位的差异。

输出记录每次的首控、完整 X/U、计算时间、自计算代价分项、初态误差、非线性 RK4 动力学缺陷、输入及变化率约束、使用返回 U 从实际状态重新积分的 rollout 及其代价。代价采用原离散模型的 dt 缩放和非 dt 缩放终端项；没有声称从求解器直接读取 NLP 代价。独立 Python 审计以同一参数的动力学方程重新计算 RK4 与代价，且检查 NaN、错误首控、错误代价、错误 rollout 和虚假 KKT 标记均会被拒绝。

## 4. 已核对的时序和误差预算

原始时序为 Ready→冻结80.097061 ms；首个 Worker 原生调用0.384360 ms，其中记录的后端时间0.364745 ms；候选就绪→约定目标时刻194.412857 ms；Ready→首个左推力 API 调用278.386803 ms。双调用均返回时为278.423407 ms。这些是实际记录的单次观测，不是 WCET、物理执行器响应或真实船体时延证明。

从只读 SQLite CDR 反序列化的 Odom/Applied 与原模型记录逐项核对：首个候选控制调用前13个样本的 surge 都为零，SSE=0.0325，占完整门限允许 SSE=0.05535943040679929 的58.7073%。调用后到1秒的37个样本另占74.7467%；1～2秒占7.1493%。因此前2秒累计已占完整允许预算140.6033%，不能靠末窗贴合通过原全窗门。

原全窗1013个样本 RMSE=0.009234946529021685 m/s；原门限0.007392495755251466 m/s，保持失败。首个命令前的零速样本只解释预算的一部分，不能将全部失败单因归于调度。后续重复 RTI 的结果需要单独解释。
