# W2 登记批：验证发现的真实缺陷与修正

_2026-10-23。四个独立视角对抗性验证 W2 registration 的可消费性，确认 4 条 critical。_

## 已确认并修正的缺陷

| # | 严重度 | 问题 | 修正 |
| --- | --- | --- | --- |
| 1 | critical | `index_sha256` 写成了合同自身 hash（`3a8451d5…`），但 Driver 硬编码断言 `INDEX_SHA='d1a9f0e2…'`（冻结证据标记）。所有 run 在启动任何角色前就 AssertionError。 | 写 `INDEX_SHA` 常量，`index` 指向 56 包的合同路径（与 W1/W3/W4 登记一致） |
| 2 | critical | `output` 写成 `<pkg>/runs/W2_01`，但 Driver 断言 `out.parent == <implementation>/runs` | 改为 `OUT / 'runs' / 'W2_01'` |
| 3 | critical | `source_bundle.json` 的每行只有 `{bytes, sha256}`，而 Driver 的 `verify_bundle` 执行 `pin(row['path'])` → `KeyError: 'path'`，身份链在 fixture 角色就崩 | `freeze_and_build.py` 每行加绝对 `path` |
| 4 | high | Driver 从 `w2_result` **顶层** 读 `guard_ns`，但 Worker 把它嵌在 `boundary` 子对象里 → 隔离时序检查恒为 False，正确 run 永远判失败 | 从 `w2_result['boundary']['guard_ns']` 读，保留顶层回退 |

前三条是**登记无法启动**级别的错误，第四条是**正确 run 永远失败**。它们都不是代码逻辑缺陷，而是"写了但没人读/读错位置"的接口错配。

## 同时补齐的消费缺口

62 号要求"新字段必须由最终 Driver/审计实际消费"。本轮把此前只写在 JSON 里的条款接进了最终判据：

- `expected.target_job_candidate_registered` / `target_job_candidate_published` —— 读 Regulator 的 `candidate_registration`（含 `accepted_registration`）与已发布集合
- `expected.target_job_native_calls` —— 读 Worker 边界记录的 `ordinal_at_call`
- `expected.backend_terminal` —— 读 Worker 的 terminal 行与 `worker_summary.fatal`
- `expected.active_job_cleared` —— 读 capability payload 的 `fatal && active_job==0`
- `expected.pending_discard_required` —— 读 `pending_discarded` 行

## 未采纳的候选（附理由）

| 候选 | 判断 |
| --- | --- |
| `two_deadlines` / `release_preconditions` 未被读取 | **接受为已知边界**。这两个块描述的是运行政策（gate 窗口 vs Job 截止），当前由 `w2_release.wait_budget_ns` 与 Worker 的 `deadline_steady_ns` 实际执行；把它们逐字段对账需要新的运行时通道，超出本次收口范围。已在文档中标注为"未消费条款"，不声称已验证。 |
| `channel.*` 未读取 | 同上。通道方向由 `w2_entry::validate()` 的 `F_GETFL` 检查强制执行，`channel` 块是描述性的。 |
| `acados_runtime` 未被消费 | **真实缺口**。Registry 固定了 libacados/libhpipm/libblasfeo 的 hash，但没有代码在运行时比较。这是"能在构建与运行之间换掉 acados"的风险。本批未修，列为登记前待办。 |
| `reused_from: attempt18` 无消费方 | 诚实标注，无强制。可接受，但应补 provenance 文件。 |
| `source_bundle_macro_present` 强度有限 | **接受并标注**。只证明 64-hex 串出现在 ELF 里，不证明它来自 `P1_OWNED_SOURCE_BUNDLE_SHA256` 宏。确认强度边界已写入本记录。 |
| Gate `run_seq` 两侧都是字面量 1 | **不是致命 bug**（两侧一致，帧会被接受），但 `run_seq` 不绑定任何东西。已记录为已知边界。 |
| Regulator W2 准入只查 job_id/ordinal 正数，不查 nonce | **真实缺口**。Regulator 的 W2 分支没有把通道绑定与 registration 的目标对账。本批未修，列为待办。 |

## 验证方式

四条视角分别审查：身份链、registration 消费、Regulator 准入、Worker 帧绑定。四条都独立指出了 `index_sha256` 与 `output` 两处，说明这是确定性缺陷而非视角偏差。
