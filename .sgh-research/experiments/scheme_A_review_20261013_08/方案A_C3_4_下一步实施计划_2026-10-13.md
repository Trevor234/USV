## A. 发布协议一致性：优先级最高

**目标：** 最终路径首次可见时就满足原 reader 的 single-link/稳定文件合同；create-only 不覆盖、nofollow、有效期和部分可见异常语义保持。

**涉及代码：** N10 的 `owned_release.py:create_only_json`、C++ `p1_startup::write_create_only`，以及实际使用公共 create-only helper 的 publisher/owned manifest/fixture 路径。先列调用矩阵；只改受影响路径并重建对应二进制。

**实现步骤：**

1. 在实际运行文件系统上核验“同目录临时文件 + `renameat2(RENAME_NOREPLACE)`”支持及 EEXIST 语义。不能用覆盖 rename/os.replace 代替 create-only。若平台不支持所选原语，应在释放前明确拒绝，另登记可审查方案。
2. 封装统一发布原语：写完并 fsync 临时文件，原子地以不可覆盖方式发布单链接目标，再 fsync 目录。路径/FD 约束与资源界保持。
3. 保留目录持久化失败后的“目标可能已可见”事实、内容 hash 和原异常。publisher 可以在 driver 返回前读取已可见授权；不能用 driver exception 推断文件未发布、publisher 必为 Held 或输出必为零。
4. 改动后先源链接原 reader/gate 做确定性并发测试，再做正常 owned fixture。禁止靠延长 3 s、去掉 nlink 检查或裁剪失败帧取得通过。

**必要验证：**

| 场景 | 判据 |
|---|---|
| 发布前读取 | 未见文件保持 Held，不制造 arm/receipt |
| 正常可见文件，在目录 fsync 返回前读取 | nlink=1，原门能按原规则接受；保持时间事件真实顺序 |
| 原 R1 确定性屏障 | 新原语不暴露双链接目标，不能出现同样的永久 Fault |
| 目标已存在/重复发布 | 旧目标字节不变，create-only 明确失败 |
| foreign hardlink、symlink、FIFO、内容/身份改变 | 原拒绝规则不回退 |
| 写入或文件 fsync 失败、尚未发布 | 明确未发布，原件/异常保留，有界关闭 |
| 目录 fsync 失败、已可见 | 独立记录可见/持久化/门终态；不授予正常链，不伪造零输出 |
| 正常 release、真实 expired | 完整 Source/transport/storage/终态对账；expired 原规则 failclosed |

**退出条件：** 新原语的实际文件系统支持、确定性边界、原 nlink 等拒绝回归与当前 owned 正例全部满足；受影响 source/bin 被锁定。单项通过不授予 C3_general 或 execute。

## B. checker 精确类型与 finite 规则

**目标：** 原生 uint/int 计数和时间不能被 bool/浮点/字符串替代；非有限数与溢出不以“strict JSON”名义进入证据。

**涉及代码：** N10 `check_release_observation` 的 gate/session/stream/ledger/cleanup/time 字段；审查共享 JSON 解析与参数 canonical helper 的类型规则，避免仅修复一个比较点。

**实施：** 建立版本化字段域，整数用 `type(x) is int` 与实际 int64/uint64 范围，bool 用精确 bool；所有需要 finite 的浮点显式验证，包括 JSON 指数溢出；nullable 字段只有“未读取”时为 null。保留正常/expired 与 ambiguous-IO 的独立预期，不把 false 改成正常 true。

**必要验证：** 原 69 个 Python 身份中受影响部分及正常/expired 对照；本次 true→1、false→0 反例必须拒绝；补 1.0/0.0、负计数、范围溢出、字符串、null、NaN/Infinity/1e309 等边界。类型/解析失败与 coherent 语义造假分列；实际录制原件不修改。

**退出条件：** 原合法证据仍通过，非法类型在相应字段规则处拒绝，原完整 transport/storage 对账保持。不得用“新例通过”替代旧正常 Witness 政策。

## C. last-valid lease 状态重放及有限异常来源

**目标：** 离线规则与原 callback 一致：invalid/foreign 不续期；匹配 fatal/instance change/expiry 终态不可恢复；有效包也不能复活已终止 run。

**涉及代码：** N10 `check_atomic_observation`、`validate_readiness` Capability 部分、实际 Capability 来源观测与专用有界 wire fixture；正常人口校验作为兼容模式保留。

**实施步骤：**

1. 从原 callback 推导身份、资源、valid、renew、check-before-renew 和 terminal 转移，重放 last-valid、worker_valid、worker_unusable、实例。独立计算并核对日志 before/after，不能直接信任 `renewed`。
2. 绑定每个实际读取的门操作数与原提交窗口；短路未读保留 null。不能仅从 Decision.reason 推 lease，也不能凭新诊断写入时间创造全局总序。
3. 先做原回调/独立离线有限矩阵；再单独设计认证异常 wire 组件 fixture，记录实际 writer GID/CDR/callback/source/storage。若新增证据 producer，必须登记独立角色和许可模式；不可放宽正常 owned 全局图门或启用 Worker 故障 hook。
4. 只有真实来源链到位，才声明这些异常 payload 的 wire 覆盖。源链接 callback 和 AST 复现分别计数，不代替 wire。

**最小矩阵：** valid→invalid、valid→foreign、资源拒绝、matching fatal、matching instance change、恰好 timeout、timeout+1、重复有效 payload、到期后有效包、无有效续期的提交。对 renewed/before-after/terminal/worker_valid 的 coherent 篡改做语义负例。

**退出条件：** normal-only 不回退；原回调、离线转移、门读取与声明的异常 wire 来源逐项一致；无法证明的 packet freshness/全局时钟仍 unknown。

## D. 实际 receipt/IO/timeout 边界

**目标：** 使用 C3.3 真实终态和原 create-call 观测解释新有界案例，不猜测旧 timeout 原因。

以 A/B 锁定的新版本，先源链接覆盖 telemetry arm 失败、arm 后到期、receipt 已可见但 I/O 未完成/失败、receipt 后到期、已 Released 后完整性改变、关闭并发。再只为明确缺口建立真实有界 owned 案例。

报告应同时包含 driver call、文件可见性/内容、publisher 原读取/arm/receipt/final/commit、Source/session、transport/storage 与监督关闭。prepared receipt 不等于 Released；driver 失败不等于未发布；normal=false 与预期拒绝组件通过可以同时成立。

不得增加正常路径诊断文件 I/O、轮询补读、期限重置或放松超时。旧两次 receipt-timeout 继续 unknown；新案例根因只能归属于新案例。
