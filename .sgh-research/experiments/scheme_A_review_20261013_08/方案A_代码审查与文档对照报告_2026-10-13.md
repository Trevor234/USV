## 1. 按优先级排列的发现

### R1 / P1：合法 create-only 发布存在瞬态双硬链接，与读取门冲突

**触发：** publisher 在 Python 写入函数已经 link 出最终 release 文件、但目录 fsync 与临时文件清理尚未结束时读取它。

源码证据：

- [owned_release.py:86](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/owned_release.py:86) 使用 `os.link(temp, p)` 发布，随后目录 fsync，到 [第 96 行](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/owned_release.py:96) 才 unlink 临时路径。因此最终文件可见期间可以有 `st_nlink=2`。
- [p1_startup_gate.hpp:124](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/publisher/include/usv_mpc_cpp/p1_startup_gate.hpp:124) 要求 single-link regular file，遇到 `st_nlink!=1` 立即抛错。
- [poll_release 的异常路径](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/publisher/include/usv_mpc_cpp/p1_startup_gate.hpp:358) 经 [fail_locked_](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/publisher/include/usv_mpc_cpp/p1_startup_gate.hpp:486) 进入永久 Fault。后续即使链接数恢复为 1，也不再接纳。

**本次复现：** 直接包含原 C++ header，以原 Python `create_only_json` 写入；只在测试中暂停它的目录 fsync。正常对照进入 Released；交错案例在链接数 2 时进入 `release_read` Fault，原因精确为 `gate input is not a bounded, single-link regular file`；arm 未调用。writer 随后正常返回，链接数恢复 1，原读取函数能够读文件，但同一 gate 再 poll 仍拒绝。两个原生探针进程均退出 0。

**影响：** 合法准备链可以因写读时间交错偶发失败。它是可用性/协议一致性缺陷；本次没有证明不安全物理执行，也没有证明历史两次 receipt-timeout 的根因。

**修复方向：** 在新派生版本统一 create-only 发布原语，让最终路径首次可见时已满足原 reader 的 single-link、身份与稳定读取合同。可选方案是同目录 `renameat2(RENAME_NOREPLACE)`；先核验实际文件系统支持，再决定实现。保留不可覆盖、nofollow、有效期、目录持久化错误与部分可见状态，不能通过删去 single-link 检查或加重试/延长期限掩盖冲突。C++ create-only helper 也使用 link/unlink，应审查其所有受影响调用点。

证据：[复现结果](/home/trevor/USV/.sgh-research/experiments/scheme_A_review_20261013_08/publication_link_race_result.json)、[复现脚本](/home/trevor/USV/.sgh-research/experiments/scheme_A_review_20261013_08/reproductions/reproduce_link_race.py)、[原 header 源链接探针](/home/trevor/USV/.sgh-research/experiments/scheme_A_review_20261013_08/reproductions/probe_publication_link_race.cpp)。

### R2 / P2：释放 checker 接受 bool 冒充整型计数

**触发与位置：** [check_gate:166](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/check_release_observation_v1.py:166) 只比较 freshness count 是否等于 1；[check_source_session:183](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/check_release_observation_v1.py:183) 与 [expired stream 检查:445](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/check_release_observation_v1.py:445) 也直接比较若干计数与 0。Python 中 `True == 1`、`False == 0`，缺少精确类型验证。

**本次复现：** 原 expired run 的完整 `analyze()` 对照通过；在 reader 返回字节处仅做内存覆盖：

| 输入变化 | 原 checker 结果 |
|---|---|
| freshness read count：1 → true | 仍 passed，结果中计数类型为 bool |
| unarmed 时间/调用计数和四流计数：0 → false | 仍 passed，transport/SQLite 与 session 组件也 passed |
| freshness read count：1 → 整数 2 | 正确拒绝：expired_short_circuit_counts_differs |

全部原运行文件保持字节不变。这是原整体检查函数对模拟 JSON 字节输入的复现，不是实际 wire、磁盘原件变更或新运行。

相邻 [strict_json:45](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/check_release_observation_v1.py:45) 仅拒绝 NaN/Infinity token，`1e309` 仍在 parser 层变成 infinity。此项只证实 parser 接受溢出数，未证明它能绕过所有后续字段门。

**影响与修复：** checker 不能把这些非法类型判为“精确捕获的原生计数”。在新版本统一验证整型范围、bool、finite 与 nullable 字段；类型失败与语义反例分别计数。原诚实记录中的整数与历史通过结果不回写；没有证据表明本次问题导致控制端执行非法动作。

证据：[完整 analyze 字节覆盖结果](/home/trevor/USV/.sgh-research/experiments/scheme_A_review_20261013_08/release_checker_type_reproduction.json)、[脚本](/home/trevor/USV/.sgh-research/experiments/scheme_A_review_20261013_08/reproductions/reproduce_release_checker_types.py)。

### R3 / P2，已登记缺口：最后 receipt 不等于最后有效续期

[运行端 capability:408](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/observer/src/shadow/regulator_shadow_observer.cpp:408) 对非终态 invalid/foreign 保留旧 lease，只在 renewed 时更新 last-capability；[离线 checker:760](/home/trevor/USV/.sgh-research/experiments/p1_execution_architecture_20261005_01/authored_D1_C3_3_20261012_v9/check_atomic_observation_v2.py:760) 却取所有 admission 最后一条并要求有效。

有效续期 → 普通 invalid/foreign → 租约仍有效的提交，会被该局部门错误拒绝。独立审查用原 AST 与保留原生回调记录确认两例差异，实际正常 run 的相关局部门通过。继承的 normal-only 全人口校验也需要兼容设计，不能只改 `cap[-1]`。

这已写入原 C3.4 计划。当前 checker 明示仅认证正常人口，本次未确认影响已有正常 fixture 的新运行端 lease 缺陷。下步须重放有效续期、终态、实例变化、到期先于续期检查和门实际读取，再补受管异常 wire 来源。
