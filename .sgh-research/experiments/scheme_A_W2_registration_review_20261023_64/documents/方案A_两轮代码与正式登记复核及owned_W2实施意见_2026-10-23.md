## 5. 仍需处理的具体问题

### 5.1 P2：早期认证失败仍会阻止driver_result落盘

位置：[观察集合初始化](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/owned_m4_diagnostic_driver_v1.py:406)、[finally读取集合](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/owned_m4_diagnostic_driver_v1.py:838)。

registered_job_ids、published_job_ids、w2_terminal_evidence仍在bootstrap完成后才定义。Fixture/Worker/Recorder/Regulator认证若提前失败，原错误已进入journal、角色与fd也已经关闭，但W2最终分支读取未初始化集合，再抛UnboundLocalError，driver_result.json不会落盘。

本次使用原最终分支和函数局部作用域复现了该错误；没有启动角色。这是E2基础变量前移后的新观察字段遗漏，不是说原fd修复没有发生。

最小修正：所有观察集合与终局结构在try前给安全默认值；已有error时最终结果明确为false，仍发布首个错误与关闭事实。finalization不应因缺观察数据再次抛出而覆盖失败。

### 5.2 P2：最终判据尚未完整交叉核对原始事实

位置：[terminal收集](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/owned_m4_diagnostic_driver_v1.py:435)、[publication证据来源](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/owned_m4_diagnostic_driver_v1.py:563)、[最终判据](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/owned_m4_diagnostic_driver_v1.py:838)。

最终分支检查disposition=expired和actual_native_invoked=false，但没有同时要求嵌套released=true、gate_outcome=released以及guard_ns大于该Job原deadline。terminal收集把任意Job的terminal行当成目标Backend终端事实。

原源码AST的隔离反例结果：

| 输入 | 当前passed |
| --- | --- |
| 合法基准 | true |
| 标为expired，但released=false／gate_outcome=timeout | true |
| 标为expired，但guard尚未过Job截止 | true |
| terminal来自Job999，而非登记Job2 | true |

这是验证器接受条件缺口，不代表当前正确Worker会自然输出这些矛盾记录，也不等于已经发生伪通过owned run。它说明本次Driver PASS还不足以独立证明W2义务。

另外，published_job_ids来自Regulator的accepted_registration，不能证明Worker是否publish。当前同时禁止任何target registration，会拒绝不少发布异常，但“目标未发布”这一子结论仍需Worker candidate_publish_result及Recorder实际记录支持；不能用注册接受替代发布事实。

最小修正：对照同一target Job/ordinal的boundary、terminal reason、原deadline与实际guard；用真实Worker发布调用结果构造publication集合；pending按实际收到集合逐Job对账。将这些反例接入Driver最终判据测试或独立W2审计，并让报告明确何者作最终资格判定。

### 5.3 P2：目标在真正准备后拒绝，Boundary仍可能写allowed

位置：[Backend final_guard短路](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/w2_author/worker/owned_cold_backend.hpp:32)。

E3通用stop/deadline先return false，目标的permit_native_entry在它之后。因此gate已允许、随后真正准备窗口发生stop/过期时，C正确被拒绝，但目标Boundary还没有刷新disposition和时间；catch只是复制旧allowed记录。

本次真实Backend精简探针输出：两条准备后stop/过期路径均抛blocked_at_final_guard，native_call_count=0，actual_native_invoked=false；但Boundary/policy仍为allowed、旧guard_ns和旧past_deadline_ns。长等待正控则正确为released→expired、C调用0。

**这不是C放行漏洞，也不阻断当前两拍后已在enter内过期的长等待目标。**修正应只合并事实更新：匹配目标由permit_native_entry完成真实最终检查与记录；非目标继续通用stop/deadline检查。两类调用都保留约束，不因改变分支顺序免除任何检查。

现有三个名含Preparation的测试仍在entry_observer中注入，发生于Gate wait之前。新非目标stop测试确实能捕获删除真实final_guard，这项进展成立；它还没有证明上述匹配目标记录窗口。可以直接承接本包精简探针补准确回归。

探针程序RC0只表示成功输出JSON；其独立一致性断言为**1条正控符合、2条失败**，不能写成3/3通过。

### 5.4 运行前身份补强：库hash尚未进入正式执行认证

registry记录了三个库的hash，freeze报告也列了依赖名，但正式Driver未在Worker认证时比较实际加载库。因此“静态已固定”成立，“运行时全部闭合”不成立。这是用户已明确披露的原身份认证义务，不是本次新增的安全条件。

最小做法是在现有Worker authenticate阶段、发布peer pins/grant之前读取该pid实际maps，核对登记的库名、实际解析路径/映射身份和文件hash，保存结果；错误时在授权业务输出之前拒绝并有限清理。注册应固定可消费的库路径/解析规则，不能只将三个hash写在无读取方的JSON里。

本包提供了只读[身份核对工具](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_review_20261023_64/implementation/check_frozen_identities.py)，当前检查通过。它不启动角色，不能替代上述活进程maps校验。若修改Driver或新增被消费的验证代码，必须重新冻结bundle、更新Driver SHA、重建相应角色并新生成registry/registration；旧63原件保留。

## 6. 预检及描述性条款的准确评价

### 6.1 9步报告是部分静态校验，不是Driver启动全链重放

[replay_driver_preflight.py](/home/trevor/USV/.sgh-research/experiments/scheme_A_W2_registration_20261023_63/implementation/replay_driver_preflight.py:134)手工复制了部分判断，并未执行真实Driver main。它遗漏真实W2预检中的nonce和范围等条件。

本次只在内存将nonce改为0：手抄报告仍9步全过，真实Driver W2预检If的AST正确断言拒绝。没有修改registration，也没有执行out.mkdir或spawn。

所以当前合法registration不因此被证明错误；应把现有证据称为“9步部分静态校验”。后续优先提取Driver和replay共用预检函数，或安全执行同一段真实语句。CURRENT中的“20项全链”与实际9步骤也应统一。

### 6.2 描述性字段当前自洽，不必新建运行时通道

本次用已固定合同、w2_release和expected字段做14项独立一致性检查，全部成立：1.5s gate窗口、150ms Job截止、2拍、600ms租约、1s watchdog、角色信号/退出值等目前没有相互冲突。

1.5s最大等待窗口不等于允许成功释放晚于1s watchdog；若错过成功刺激窗口，该run应失败并按原规则收尾，不能延长watchdog。

two_deadlines、release_preconditions、channel.*没有逐字段被Driver读取，应继续诚实标注。但静态一致性预检可以直接利用现有config和参数；运行后核对也已有Job/Boundary/capability/Source/manifest数据。**无需为这些比对新增一套DDS或pipe通道。**

如果它们被定义为强制条款，就让预检/审计检查并拒绝冲突；如果只是派生说明，明确唯一权威字段与派生关系，不能声称它们支持任意配置。不同镜像字段不可静默漂移。

### 7.3 一次最小owned W2，自动重试0

| 时段 | 本次应收集和判定的事实 |
| --- | --- |
| 启动授权前 | 四角色、工具、bundle、ELF、运行库、manifest/端点/Recorder身份一致，Source准备完成 |
| 前序正常段 | 有登记要求的正常求解/接受前缀，不把首Job四次冷启动调用误算为目标调用 |
| 目标驻留 | 目标内部边界真实进入；至少两条不同完整业务tick在其后；真实capability续租；active/pending/ready有界 |

| 原截止拒绝 | guard超过目标原deadline；目标实际C调用0；无目标candidate发布、注册或激活 |
| 终端隔离 | 正确目标expired/terminal；Backend保持不可用；active=0；实际pending集合逐Jobdiscard，不伪增正常completed |
| 关闭 | Worker RC2及登记信号；其他角色按既有规则；API、Source、Recorder存储、flush及进程组清理完整 |

45s Driver预算、既有INT/TERM/KILL边界、自动重试0保持。任何失败都保存本次原始证据，不覆盖旧run；如果registration要求必须存在pending discard，须确认该刺激确实产生pending。没有pending时不伪造discard或跑后改登记，应如实记当前条款是否覆盖。

### 7.4 运行后独立审计决定能提升什么

Driver PASS只作运行器初判；独立W2审计按原始身份和Job多重集核对release、C调用、发布/注册/存储、过期/替换/discard和关闭。补齐真实心跳、槽位、API/Stored义务后，才更新原47矩阵的native-boundary对应子项。

接着仍按Fixture与原九组差集→M4复判→有限模型事务/F6→P1。一次W2通过也不会自动使完整M4/F6/P1、plant或硬实时变true。
