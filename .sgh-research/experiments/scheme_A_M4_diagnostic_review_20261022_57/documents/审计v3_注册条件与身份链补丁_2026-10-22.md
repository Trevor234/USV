## 2. 根因（比审查文档记录得更具体）

审查文档把身份问题归为“检查没有闭合到实际 ELF”。实际根因更直接：`check_role_identity()` **已经实现但从未被调用**。主流程只调用了 `check_contract_identity` 与 `check_roles`（v2 的 1046–1047 行），而负责 `registry → manifest → 实际 ELF → source bundle` 的那条链从未进入审计路径。所以把 Worker manifest 的 `binary_sha256` 改成全 0 仍然通过，不是因为检查太弱，而是因为检查没有执行。

同理，注册刺激与 case 特有条件没有任何独立函数：`check_transition` 只比对 reason 文本，`check_worker_hooks` 在 W3 只要求延迟非负，`check_worker_accounting` 只看 active 指向已知 Job；这些都不足以发现“刺激根本没发生”。

## 3. 补丁内容

派生自 v2 的新副本：`implementation/audit_v3/audit_diagnostic_v3.py`。仅改动审计工具，不触碰产品或 56 包。

### 3.1 身份链闭合（修 2.3）

- 主流程现在调用 `check_registration_pins()` 与 `check_role_identity()`。
- `check_role_identity` 逐角色核对：registry 记录的 ELF hash ↔ 磁盘实际 ELF ↔ run manifest 的 `binary_sha256`/`exe` ↔ source bundle 成员逐文件 hash；再核对 Driver 脚本 pin 与三角色加载的完整 typed 配置等于运行合同。
- `check_registration_pins` 的路径比较改为解析后比较：launch 回执记录的是相对包根路径，直接字符串比较会误判。

### 3.2 case 专用独立检查（修 2.1）

新增三个函数，直接读 registration 的 `expected` 块并测量，而不是重述 Driver 的 `passed`：

- `check_case_W1`：独立重算转移瞬间的租约年龄（`check_ns − capability_last_valid_commit_ns`），要求 `< capability_timeout_ns`，从而把“watchdog 触发”与“租约过期”分开；要求注册的 stall 真的存在、时长不低于注册值、且**跨过**转移瞬间（这是 watchdog 触发的因果证据）；要求 stall 期间确有 capability 心跳；要求转移后没有已接受决策。
- `check_case_W3`：从 raw 时间重算投递延迟并与注册的 `worker_delay_ms` 对比；要求 solve 时间戳未被改写；要求对应候选的注册 `reason == "late"`、`accepted_registration == false`，并且**实测** `ready_commit_ns > job.deadline_ns`（本例迟到 24.11 ms），而不是只信 reason 字符串。
- `check_case_W4`：要求被丢弃 Job 的目标 tick 存在、未接受、决策为 `no_candidate`；该 Job 不进入 `candidate_registration` 也不进入 bag；在“丢弃发布点 → 下一 Job 到达”的精确 idle 窗口内，每帧 capability 的 `active_job == 0` 且 `pending_count == 0`；之后至少一个 tick 恢复接受。

### 3.3 capability Source ↔ Stored 对账（修 2.1 后半）

新增 `check_capability_source_vs_stored()`：把 Worker `capability_publish_attempt` 的 payload 与 bag 中 `/p1/worker_capability` 的已存储消息做**完整 typed 多重集**比较。三例计数 16/16、8/8、11/11 全部相等。

W4 的 idle 反例因此有**两层独立保护**：修改 Source payload 同时破坏了“Source ↔ Stored 一致”和“idle 窗口 active==0”。运行探针时先命中前者（`capability Source payloads differ from the Stored set`），但后者在自己的变异自检里也被验证——`W4_audit_v1.json` 的 `mutations_rejected` 含 `idle_window_active_not_cleared`，对应断言原文是 `capability still reports active job 3 in the idle window after drop 3`。两层都真实生效，不是一层顶替另一层。

### 3.4 变异准备与断言分离（修 2.3）

`must_reject(name, prepare, check)` 拆成两步：

1. `prepare()` 返回被篡改的输入；无法施加时返回 `None`，记入 `mutations_inapplicable`，**不计为拒绝**。
2. 先断言输入确实改变，再调用被测检查；只把 `AssertionError` 记为拒绝，其他异常单独记为 `escaped`。

这正是原工具把 W3 `m_hold` 的准备期 `AssertionError('no hold decision to mutate')` 计进 7/7 的原因。现在 W3 的 `silent_hold_ramp` 明确列为 `inapplicable`，代之以真实存在的 `zero_delivery_delay`。

另加完成门槛：每个 case 必须由其**注册条件**对应的变异实际拒绝（W1→`expired_lease_at_transition`、W3→`zero_delivery_delay`、W4→`idle_window_active_not_cleared`），否则审计失败。这样“资格覆盖”不能再靠无关变异凑数。

### 3.5 结果文字更正（修 3.5）

W1 的 claim 由 `watchdog must not fire` 改为与实际相符的：`the active watchdog fires after the registered stall while the capability lease is still valid; the heartbeat stays live`。W3/W4 的 claim 也改为逐项列出注册条件。

## 5. 边界

- 本补丁只提升**审计器**对现有记录的判断能力。它不产生新运行证据，也不改变三例的限定组件结论。
- `probe_*/postrun` 中出现的 `passed=true` 是原 v2 漏检的证据；v3 对应目录中这些输入均被拒绝。两者不可混读。
- 完整 M4、F6、P1、plant 接受、硬实时与研究结论仍为 false。
- 未复核 47/49/50/51/53 全部历史目录，也未逐项检查 superseded 材料。
