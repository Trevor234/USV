## 2. 做了什么

### 2.1 W4 公共收尾（Worker）

`continue` 改为标志位：丢弃只跳过 `out_->publish()`，`completed_++`、`active_=0`、
数值失败策略与发布路径**完全一致**。`terminal_numerical_failure` 的
`result_published` 从硬编码 `true` 改为真实值。

### 2.2 目标 tick 补证（Driver）

Driver 现在必须完整走完这条链才允许宣告通过：

```
Worker diagnostic_candidate_dropped(job_id)
   → Regulator job 行反查 target_tick
   → 该 tick 决策必须是 no_candidate 且未接受
   → 该 job_id 不得出现在 candidate_registration
   → 至少一个后续业务 tick，且其中必须有接受（投递恢复）
   → 丢弃后、下一 Job 前的 capability 窗口内 active_job=0 且 completed>=生成数
   → hold/ramp 由 hold_ns 独立复算，不采信 control_source 字段
```

### 2.3 独立审计（`audit_diagnostic_v2.py`，新增）

不是 53 批审计的移植，因为两批的**可对账对象不同**：

| | 53 批（R1/R2/R3） | 本批（W1/W3/W4） |
| --- | --- | --- |
| 被测现象 | 进程死亡/冻结 | 活着的 Worker 按注册钩子出错 |
| 对账单元 | 进程与转移 | **每个 Job 身份** |
| 关键风险 | 漏判失活 | 把"按策略丢弃"与"真丢失"混为一谈 |

因此审计以 **Job 为键做多重集对账**，每个 Job 必须恰好落到一个终局：

| 终局 | 含义 |
| --- | --- |
| `delivered` | 生成并发布 |
| `dropped` | 生成后按策略不发布（W4） |
| `expired` | 在 pre-native 截止检查处被丢弃 |
| `replaced` | 单槽 pending 被后续 Job 顶替 |

并强制：Worker 收到的每个 Job **必须**有且仅有一个终局；不得出现 Regulator 从未发布的 Job 的终局；
同一 Job 不得有两个终局。**7 项变异自检**全部必须以 `AssertionError` 被拒（非断言的
`KeyError` 不算通过——这条纪律本身就是这轮加的）。

### 2.4 Fixture 起跑缺陷（意外发现）

`fixture_start` 刚出现时立刻做 DDS 图检查，发现未收敛就直接终止 run。
改为在主循环里做**有界重试**（2 s 起跑预算内），GID / 节点名 / 唯一发布者三项校验不变。

### 3.1 W1：watchdog 而不失租约

| 观测 | 值 |
| --- | --- |
| stall 实测 | 1700.1 ms（注册 1700 ms） |
| stall 期间心跳 | 16 次尝试，最差间隔 200.6 ms |
| **转移时租约年龄** | **3.66 ms**（`check_ns − capability_last_valid_commit_ns`） |
| 租约超时 | 600 ms → **远未到期，所以不是租约路径** |
| 转移原因 | `active_watchdog` |
| watchdog 行 | 4 |
| Job 终局 | 1 delivered / 2 expired / 4 replaced |
| 转移后 | 无新 Job、无新接受候选 |

**这条是本批方法学上的关键改进**：1.7 s 的 stall 落在 600 ms 与 1 s 之间，
若不计租约年龄就无法排除"其实是租约到期"。实测 3.66 ms 直接排除了该解释。

| `worker_unusable_transition` / `active_watchdog` | 0 / 0 |

### 3.3 W4：丢弃被记账，按政策降级，随后恢复

| 观测 | 值 |
| --- | --- |
| Job 终局 | 1、2 delivered；**3 dropped**；4、5 delivered |
| 生成/发布/丢弃 | 5 / 4 / 1（精确闭合） |

| 失活 / watchdog | 0 / 0 |

## 5. 这一批额外发现的真实缺陷（均已修）

| # | 缺陷 | 后果 | 修法 |
| --- | --- | --- | --- |
| 1 | Decision 的 `diagnostic_only = mode_!="execute"` | v4 诊断 run 必须跑 `execute`，于是**每条决策都声称自己不是诊断** | 改为 `mode_!="execute" \|\| !execute_qualified` |
| 2 | `normal_contract_complete` 同样只看 `mode_` | 诊断 run 的决策声称"正常合同完整" | 追加 `&& execute_qualified` |
| 3 | `normal_source_complete = generated==published` | W4 的**已记账丢弃**被误报为 Source 不完整 | 改为 `generated==published+dropped`，并把 `dropped_candidates` 写进 summary |

第 1、2 条是审计第一次跑就抓到的——它们是**标签缺陷**，不会让任何数值出错，
但会让下游把诊断证据当成正式证据。
