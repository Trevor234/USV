# C3.4-A 发布协议修复与组件验证（2026-10-13）

本子任务完成 v10 的 create-only 发布协议修复。实际工作目录是 `/home/trevor/USV` 所在 ext4 挂载；`renameat2(RENAME_NOREPLACE)` 的正常成功和 EEXIST 不覆盖行为均实际执行验证。旧 v9 的双硬链接竞态与旧结果保持，只将旧报告复制到本证据目录作对照。

## 做了什么

1. 新增 `common/p1_create_only_atomic.hpp`，作为 owned 与 publisher C++ 共用的无 ROS 依赖写入原语。先通过 O_EXCL/O_NOFOLLOW 创建同目录独占临时文件，写完并 fsync 文件，再以原子 no-replace rename 发布最终名字，随后 fsync 目录。不存在 link/unlink 发布窗口，也没有覆盖 rename 或失败后改用其他原语的 fallback。
2. `common/p1_owned_identity.hpp` 和 `publisher/include/usv_mpc_cpp/p1_startup_gate.hpp` 接入这个原语。原 nofollow 目录 FD、owned 的 256 KiB、publisher 的 16 KiB manifest/release 资源约束保持。原 single-link regular reader 保留，发布 gate 的三个 freshness 读取、原有效期和接受/拒绝顺序保持。owned 目录 fsync 异常仍有 path/content SHA，并通过 nested exception 保留原 errno；共用与 gate 错误明确说明目标可见、目录持久化尚未确认。
3. `owned_release.py` 同样使用 `renameat2(RENAME_NOREPLACE)`。父目录由 `/` 开始逐段用 O_NOFOLLOW directory FD 固定；临时文件以该 FD 创建，rename 使用同一个 FD。target 首次可见时临时名字已消失，st_nlink 为 1。目录 fsync 失败仍抛 PublicationAmbiguousError，并保留原 OSError 对象作为 cause，目标不会被清理。发布前错误仅尝试清理本调用已经独占创建的临时名字；清理失败不替换原异常，碰撞已有临时文件也不删除它。Linux libc 无 renameat2 时 ENOSYS 失败，没有 link 或 overwrite fallback。
4. Python strict_json 补有限 parse_float，拒绝 `1e309`、`-1e309` 等解析溢出，以及原先已拒绝的 NaN/Infinity 和重复键；正常有限 IEEE 值与负零可解析。
5. 新增 `test_create_only_atomic.py` 的 14 项实际 IO/合同边界测试。原 publisher 56 个测试身份不变，仅将一次旧 atomic-link 错误字符串改为新的 no-replace-rename EEXIST 原因。

源链接原 gate 的 10 项分别为：正常发布、目录 fsync 暂停、目录 fsync 失败、文件 fsync 失败、写入暂停、写入失败、重复目标、symlink、FIFO、hardlink。关键结果是：**目录 fsync 尚未返回时 writer 仍在运行，目标已经 nlink=1，gate 能按原规则进入 Released。** 写入暂停时目标尚不存在，第一次 poll 保持 Held，恢复写入后的第二次 poll 可 Released。write/file-fsync 故障保持 target 缺失；EEXIST 保持原字节和 inode；三种 reader 非法目标仍进入 Fault，不调用 arm。多硬链接案例保持原精确拒绝原因，没有删除 single-link 保护。

共用 C++ 七项分别为：正常、EEXIST、EINTR 后短写循环、写入 ENOSPC、文件 fsync EIO、目录 fsync EIO、rename ENOSYS。目录 fsync 错误保留已发布 target、nlink1 和实际 EIO；所有已创建且可清理的本调用临时文件正常消失。

目录 fsync 失败这个边界尤其需要分清：Python writer 报告可见但持久化不确认，原 gate 仍可能读取并接受可见的合法 release。这证明文件可见性、writer 成功返回和 gate 接受是不同事件。它不是正常全链通过，也不证明没有物理输出；本探针没有 ROS、输出端或 plant。root 的真实有界运行与 terminal evidence 必须单独审查。
