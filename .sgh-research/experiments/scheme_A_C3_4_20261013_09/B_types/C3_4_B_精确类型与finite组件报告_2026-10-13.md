# C3.4-B：精确类型与 finite 组件报告

日期：2026-10-13；本节只处理新 N10 代码和离线验证。没有启动 ROS，没有更改 N9 录制、冻结源或原失败证据。

## 修改与作用

| 文件 | 实施内容 | 作用与边界 |
|---|---|---|
| `strict_types_v1.py` | 新增版本 `p1-C3.4-exact-field-domains/v1`；原生计数/序号为 exact `int`、uint64；时间为 exact `int`、非负 int64；进程标识/返回码为有符号 int64；旗标为 exact `bool`。nullable 时间只在声明过的观测字段允许 null，随后沿用原 case 语义检查实际未读。 | 避免 Python 的 `False == 0`、`True == 1` 或浮点整数等价判定混入原生证据；类型成立仍不代表因果/来源/期限成立。 |
| `check_release_observation_v1.py` | schema 升为 `p1-C3.4-release-observation-check/v2`；在 gate/session/streams/result/cleanup/ledger/身份/receipt/metadata/transport/terminal 等入口调用字段域；JSON 树拒绝非有限数和超出原生 64 位联合域的整数；SQLite 原始时间沿用 signed int64。 | 保持既有 Source/存储、SHA/GID/作者、清理、3 秒 helper 和 60 秒范围/运行预算等语义门。正常/expired 和 ambiguous IO 原预期不变。 |
| `owned_auth.py` | 参数 `type` 保持 exact int；double 与数组元素必须 finite，超大 Python int 的浮点转换溢出也转成明确拒绝；typed canonical 比较改为递归精确类型比较；进程/source-FD/graph/prepare 时间接入字段域。 | 例如 bool 参数的 `canonical_value=1`、int 参数的 `canonical_value=false` 原先 Python 等价比较可接受，现拒绝。双精度整数文本仍按原协议转换 binary64；有符号零位型仍不同。 |
| `test_strict_types_v1.py` | 32 项新 unit，含各字段域和 parser/参数边界。 | 仅组件输入域覆盖，没有声明实际异常 wire 覆盖。 |
| `replay_strict_types_v1.py` | 在只读 N9 原运行上调用完整 `analyze`，可控制读取到的 JSON 字节覆盖；保留真实作者路径、源码/构建 pin、transport 和 SQLite 原件。 | 完整 checker 重放，不是新运行或认证来源语义伪造；非法类型和解析拒绝单独记为 representation rejection，`semantic_negative_pass=false`。 |

原 native counter 的 uint64 允许值 `0…2^64-1`；有符号字段允许 `−2^63…2^63−1`，时间字段额外要求非负。对应 deadline、receipt、commit 等是否必读/先后成立仍由原 gate case 的检查决定。未读字段允许 null，不容许用 false 或 0.0 代替 null。

## 依赖与历史兼容

新的 driver 必须捕获 `strict_types_v1.py.snapshot`，其 SHA256 同时匹配 `inputs.tool_sha256` 与实际 checker 依赖。缺少该来源不得以新 N10 身份通过。

N9 兼容例外仅允许原 `authored_D1_C3_3_20261012_v9` 作者目录和三项固定旧 driver SHA：`prepare_fixture.py`、`owned_auth.py`、`owned_release.py`。输出明确说明新字段域没有被旧 driver 实际执行或捕获。没有为 N9 补造新 snapshot，没有改旧作者路径。

`owned_release.py` 由 C3.4-A 独占修改。B 对其当前 finite `parse_float` 执行测试；没有修改该文件。新 checker 同时对解析后的整个树检查 finite，覆盖 `1e309` 这种不触发 `parse_constant` 的 JSON 指数溢出。

- [最终 unit 日志](final_units.log)：73/73，构成为受影响原 41 项（20 release checker、14 owned auth、7 publication observation）与新增 32 项。本计数不含父任务负责的其他原 Python 测试或 native 构建。

- 新 unit 覆盖 exact bool/int/float/string/null、负计数、int64/uint64 溢出、NaN/Infinity/±1e309、数组元素、canonical 类型和 signed zero。finite `±1e308` 与最小次正规数仍可读。
- 正常记录仍要求 Released 和三次原 freshness read；expired 保持 Fault、一次 read、其余实际未读 null、原 unarmed `normal_end=false`；visible ambiguous IO 仍是失败输入，不能折为成功或证明未发布。

完整 analyze 的两类原审查复现结果：

| 覆盖 | 旧 checker | 新 checker |
|---|---|---|
| `gate.original_freshness_read_count: 1 → true` | passed | `field_domain:gate.original_freshness_read_count:exact_uint64` |
| unarmed 的零时间/计数与四流全部 `0 → false` | passed | `field_domain:session.queue_dropped_total:exact_uint64`，第一处非法值被拒绝；unit 另逐字段覆盖每个字段。 |

其余覆盖为 freshness string/null/负数/uint64 溢出、close elapsed bool/float/int64 溢出，全部在新 checker 拒绝。额外发现仍属于表示域问题，没有证据据此声称控制端实施了非法动作。
