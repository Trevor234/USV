## 2. A 方案开始前必须闭合的四个接口问题

### 2.1 当前导出源码的物理缩放与注释不一致

事实：环境定义 `action_space=Box(-1,1,(2,))` 并在 `step` 内乘 25 N。`export_policy.py:72–73` 从 checkpoint 的 `action_space.low/high` 取导出范围；`43–47` 的输出是

`act_low + (clip(mean,-1,1)+1)/2 × (act_high-act_low)`。

静态推导：若 checkpoint 由当前 `[-1,1]` 环境训练，这个输出仍为 `[-1,1]`，没有乘 25。ROS 的 `rl_policy_node.py:258–264` 把其直接当 N 限幅/发布，最大只有 1 N。这与导出文件和 README 的“物理推力 ±25 N”说明相矛盾。

`export_policy.py:108–113` 的校验参考同样使用这一映射，因此可能图与参考一致而单位错误。不能靠该对拍断言物理缩放正确。仅凭源码时仍须考虑旧 checkpoint 来自不同动作空间，但本次随后取得的只读资产核验已确认 `v5/s4_dr` 存在这个问题。

资产确认：父任务读取的 `work/a_feasibility_2026-10-03/asset_meta.json` 中，`v5/s4_dr/model.zip` 的 data JSON 明确 action_space 两项均为 `[-1,+1]`、observation shape 为 43，记录 `num_timesteps=10092544`；未执行 pickle 反序列化。其 `policy.onnx` 输出名虽叫 `thrust`，末端实际为 `Clip[-1,1] → Add1 → Mul0.5 → Mul[2,2] → Add[-1,-1]`，代数上正好保留 `[-1,1]`。因此与现 ROS 源码共同使用时，物理命令最多 ±1 N，缺少 25 N 缩放已由现存资产确证。无需策略推理或重新训练便能确认此接口问题；训练步数只表示 checkpoint 元数据，不证明实际学习质量或本次复现性能。

最小解决：确定唯一契约，推荐 ONNX 输出归一化二维动作，部署侧显式且仅一次执行 `T_proposal=25×a_norm`，或者导出图显式包含物理范围 `[-25,+25] N` 并写 manifest。增加独立预期幅值测试：归一化 `[-1,0,1]` 的物理映射应为 `[-25,0,25] N`；同状态/同历史执行动作对拍 SB3、ONNX、ROS 建议消息。不要同时在图和 ROS 侧重复乘 25。

### 2.2 返回观测中的历史推力时序不一致

`usv_tracking_env.py:227` 先生成返回观测，`232` 才把 `self.prev_thrust` 更新为本次 applied。故 `step(a_k)` 返回的新状态观测里末两项仍是更早的历史推力；下一步训练策略拿到的不是与当前状态相配的上一控制区间执行推力。

ROS 的 `rl_policy_node.py:263–264` 先发布再保存 applied，下一周期用的是上一周期发布值。`tests/test_obs_equivalence.py:27–29` 在 `step` 后又调用 `_get_obs()`，只验证更新后的内部快照，不检查实际 `step()` 返回值，不能覆盖上述时序差异。

建议先写一个很小的序列门禁：两次不同动作，检查 `reset`、每次 `step` 返回末两维与控制区间定义。明确 `o_k` 最后两项为上一已执行区间的推力；再统一返回观测和 ROS。修复后旧策略的观测分布会变化，先保存旧行为作基线，进行冻结策略短程对拍，不能直接声称修复后性能不变。

加入安全层后，PPO 节点末两维必须来自最终执行器反馈，不能继续保存自己的建议推力。安全层限幅/限率或备份接管后的动作才是下一状态的输入。

### 2.3 训练植物与 VRX 有明确已知模型差异

`usv_rl/usv_rl/dynamics.py:39–40` 的默认附加质量交叉项是 `Yr_dot=0`、`Nv_dot=-0.363545`。`usv_mpc_ws/artifacts/vrx_model/effective_vehicle.yaml:14–15` 是二者均为 `-0.1817725`；`model_report.json` 明确记录了对称均值投影。VRX launch 的方案 B 使用生成后的 `effective_vehicle` 参数，见 `vrx.launch.py:102, 158`。

因此 Python 与 C++ 同参数轨迹对拍，即使运行通过，也不意味着原始 Python 默认植物和 VRX 植物完全一致。首选 A 应保存两套版本：与 VRX 有效参数一致的模型用作对齐门禁；原始辨识参数与有效参数之差可作为一个已知、可重复的模型失配案例。保留原辨识结果，不能把该投影说成重新辨识或凭 GP 学习“发现”新机理。

### 2.4 策略发布值、真正执行值和时间戳未形成证据链

`rl_policy_node.py:133–143` 不保存 odom/IMU 的消息时间戳，`217–218` 以最新 IMU 覆盖 odom 的 r，但没有年龄或同步检查。左右推力消息是各自独立的无 Header `Float64`，状态 JSON 中的 `actuation_anchor_source="vrx_published"` 表示发布命令，不是测得的实际推力。推力突变、通信延迟、不同步 IMU 会混入所谓“动力学残差”。

建议新增一个带 Header、sequence、source、左右推力、有效截止时间的联合建议消息，以及对应最终执行记录。GP 原始标签先用同步 ground-truth odom 的三个速度和其时间戳，避免用跨时刻的混合 odom/IMU 状态；后续对真实融合状态单独测量时间对齐/噪声影响。最终执行器记录命令的仿真时间戳、墙钟发布时间和实际持有区间，若有执行器动态再记录/估计其状态。两只 Float64 物理输出仍可保留为 VRX 兼容接口，但证书和数据集必须以同一联合执行记录为准。

另外，`train.py:157–165` 的 best-model 回调没有显示与每次最佳模型同步保存 VecNormalize 的回调，阶段结束才保存该统计（`193–194`）；检查 best/ 模型时要确认配套统计是否由其他操作生成。`export_policy.py:58–70` 在归一化文件缺失时退回零均值/单位方差并继续导出，推荐研究基线改为缺失即失败，避免资产悄悄漂移。ROS `_profile_cb` 仅按数组长度判断同步（`rl_policy_node.py:182–190`），同长度但版本不同的路径/剖面可能被接受；新增 path/profile version 或严格时间戳匹配。参数 `schedule_rebase_m` 在读取后又于 `115` 写死 2.0，新路径分支也未明确清空 `_t_lag`；做序列对拍时需覆盖重规划与任务重置。

## 3. 训练随机化和奖励的实际覆盖

`configs/ppo.yaml:50–57` 的第四阶段设水动力参数逐 episode ±20%、执行延迟 0 或 1 步（0 或 0.2 s）、u/v/r 观测高斯噪声 0.02、位置噪声 0.05。`dynamics.py:67–73` 对所有 19 个字段独立乘随机数，因此质量、桨距、阻尼和惯量都扰动，而值为零的交叉项仍为零。

这不是运行中突变、变化水流或 GP 模型切换。环境内延迟队列每 episode 固定长度，也不是随机丢包、计算超时或时间变化执行延迟。无独立模型可行性、正定性或物理一致性过滤；若扩大扰动范围，必须检查惯性/耦合子块可逆与合理性，不能只把随机化幅值提高。

`evaluate.py:113–115` 无条件关闭所有四类 DR；现有默认评估因此不能支撑失配、延迟、噪声鲁棒性结论。该评估还只提供 LOS/PPO 支路，没有 NMPC 或安全层共同场景入口。能耗指标 `evaluate.py:59` 是 `Σ(TL²+TR²)×0.2`，单位 N²s，只能称控制努力代理；不是测得的电能或焦耳，且写死 0.2 会在改周期后失配。

`_check_done` 首先检查进度成功，再检查误差，配置 `early_termination=false` 则位置/航向越界多数只在超时时记录原因。A 评估须独立累计每步约束越界和碰撞事件，不能将任务成功率等同安全率。

## 4. 首选 A 的最小接线选择

最初阶段冻结 PPO 参数和 VecNormalize，保持现有 43 维观测，拆出 `policy_proposal_node → safety_executor → VRX thrusters`。安全执行器也接收状态、模型快照、目标/障碍物预测、最新备份与版本；它是唯一物理动作出口，负责建议限幅/限率、证书检查、执行备份和发布最终执行反馈。

目前 launch 的 `scheme A/B/C` 指的是运动学 MPC / 动力学 NMPC / RL（`vrx.launch.py:42–44, 141–143`），与论文“首选 A”只是碰巧同名。报告中建议称研究方向为“课题 A”，新 launch 叫 `gp_backup_research.launch.py`，避免用户把研究直接理解为切回运动学方案 A。使用方案 B 的动力学/推力接口作为过滤器基础、C 的策略作为冻结建议器。`cmdvel_to_thrust.py:71, 126–145` 是现有运动学方案 A 的 50 Hz 内环，不能再串进直接推力 PPO/NMPC 的链路，否则动作含义和残差输入都会改变。

新增前置状态分支：无新鲜 odom、建议非有限、策略异常、模型加载失败、建议过期、执行器状态不一致时退出正常策略跟随，进入明确标记的备份/降级；“发零推力”必须称应急动作，不能自动称已认证安全。当前 RL 节点只按 infer_ms 标 `deadline_miss`（`rl_policy_node.py:284–285`），该耗时不含构建观测、安全检查、模型切换、发布和调度等待；新证书必须使用端到端墙钟预算。

## 5. 可直接采用的 GP 数据标签规范

固定采样周期阶段，定义 `nu_k=[u_k,v_k,r_k]`，`x_k=[x,y,psi,u,v,r]`；选控制区间实际保持的左右推力 `T_exec,k`，而非 PPO raw 或 NMPC 优化输出。若执行器没有显著状态，可先取

`z_k=[nu_k,T_exec,k]`，`y_k=nu_(k+1)−[F_nom(x_k,T_exec,k;Δt_k)]_nu`。

标签是离散一步速度残差，u/v 分量单位 m/s，r 分量 rad/s，不是加速度；预测加到离散速度状态，不再乘一次 dt。若要学习加速度残差需另定标签并正确积分与转换协方差，不能混用。

采样期 Δt 波动较大或区间内多次换命令，不能只用第一个/最后一个命令近似：用记录的分段保持输入重放名义积分，或者剔除该样本并记录剔除比例。明显执行延迟时，应记录队列/上一执行动作并扩展 Markov 状态或明确输入滞后；否则 GP 会把延迟误差当水动力不准。海流依赖状态/世界方向时，五维输入未必足以建模，先分场景标记，再决定增加 psi、已测流信息或漂移过程。

建议每条记录保留：episode、控制 sequence、odom header stamps、sim time、steady-clock times、命令 raw/limited/executed、保持起止、actual/estimated actuator state、名义模型 hash、GP snapshot id、误差界版本与年龄、障碍物预测版本、证书 id、拒绝原因、备份索引、状态6、坐标帧、Δt、质量检查结果。不要让证书/模型版本仅留在人类日志文本里。

遥测桥 `telemetry_bridge.py:258` 用 `time.time()` 作为汇总 t，5 Hz 快照适合监视但不是按原始消息戳对齐的数据集。直接记录 ROS bag 原始 odom/IMU、clock、最终联合执行、GP/证书状态；现有 `bag_topics.yaml` 主要是 MAVROS 真船话题，没有 VRX 新证书话题，需新建研究专用 bag 清单。首选 A 无需更改遥测 TCP 协议即可开始。

## 6. 推荐按顺序落地的最小改造

1. 只读冻结现有 model.zip、vecnormalize.pkl、ONNX、配置与 git 状态/hash；配套资产不足时不使用该 checkpoint 作为可复现基线。读取真实 action_space 后修正一次且仅一次的缩放。
2. 制定 `o_k` 与历史最终执行动作语义；修复返回观测、策略推理和执行反馈的一致性。增加同序列观测/动作物理值门禁，而非只比较两个共享函数。
3. 用 VRX effective 参数构建同参名义模型，保存原始拟合模型作为不同版本；在冻结建议器下比较简单 Python 植物与 VRX 的基准动力学误差，分清模型差异与传感/时序误差。
4. 建立唯一执行出口和带时间戳的建议/执行日志；不接 GP 先复现实验链路。使用固定解析建议或既有 LOS/NMPC 也可测试证书，避免 PPO 部署问题阻断 A。
5. 收集对齐残差数据、离线评估三维残差预测及覆盖，不在同一数据上宣称覆盖可靠。初期用有已知边界的人工模型更新测试“新模型接受/旧备份失效/超时保持”的状态机，再接在线 GP。
6. 改现有 evaluator 或新建独立 evaluator，支持配置化失配、运行中突变、固定障碍、执行延迟、超时注入和数据年龄；以同初值/同场景/同种子对比无更新、无门禁更新、只有误差 gate、完整证书 gate。
7. 初期仅做单船、静态障碍和有限时域备份，证书未接终端安全集时明确称“有限时域可执行性检查”；动态目标、真实融合状态、Pi5 和真船放在后续门禁之后。
