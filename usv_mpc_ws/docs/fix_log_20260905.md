# 2026-09-05 代码审查修复日志

对 2026-09-05 全栈代码审查发现的 P0/P1/P2 三级问题的修复记录。
修复同步应用于 `usv_mpc_ws`（开发）与 `usv_mpc_ws_B`（Pi5 部署），两区保持同源。

## P0 — 实机安全（已修复）

| # | 问题 | 修复 |
|---|------|------|
| P0-1 | 电池回调刷新 odom 看门狗时间戳，GPS/EKF 断流 failsafe 永不触发 | 电池检查拆为独立域 `update_battery()`，`update_odom()` 不再接收 voltage |
| P0-2 | `/mpc/status` 无新鲜度看门狗，MPC 死亡后 failsafe 全盲 | 新增 `mpc_status_timeout_s`（默认 1s）；armed 且 ACTIVE/HOLD 时 status 停发 → FAILSAFE RTL |
| P0-3 | Python mode_manager 收到畸形 `/mpc/status`（如 `null`）即崩溃 | JSON 载荷 `isinstance(dict)` 防御，走 legacy 回退 |
| P0-4 | MPC 全链路无 NaN/Inf 防护，NaN 推力 → 任意 PWM | odom/imu 输入门禁 + 三个求解后端在写热启动前校验解有限性，非有限按失败走分级回退 |
| P0-5 | `steering_sign` 代码默认 +1 与 ArduRover 舵向相反 | 默认改为 -1.0（与实船标定及所有 YAML 一致） |

## P1 — 功能错误（已修复）

| # | 问题 | 修复 |
|---|------|------|
| P1-A | 运行时 N/dt 与 codegen 烘焙值不一致 → 生成码越界写 | `AcadosBackend` 构造时比对 `nlp_dims_->N` / `nlp_in_->Ts[0]`，不一致拒绝启动；codegen 脚本 `--dt` 默认修正为 0.2 |
| P1-B | SIGINT 退出跳过安全停车（`rclcpp::ok()` 守卫） | `context->on_shutdown()` 钩子 + 退出兜底，幂等发送 |
| P1-C | `publish_standby_status_` 无锁读共享状态 | 加锁（对齐 kinematic 包） |
| P1-D | `allowed_fcu_modes` 与 `output_mode` 契约无校验 | 启动自检：rc_override 而清单不含 GUIDED → 显式告警 |
| P1-E | 求解失败计数按 2Hz 监控节拍膨胀，提前误触发 RTL | `/mpc/status` 加序号，仅消费新鲜状态 |
| P1-F | 规划器对畸形输入零防御（节点死亡/UB/(0,0) 航点全速开错方向） | fillet 入口有限性门禁、动态航点过滤、mission bridge 拒绝非有限与 (0,0)、Python `_publish_path` 兜底（异常发空路径保节点存活） |

## P2 — 质量隐患（已修复）

- Python 安全包看门狗时间戳全部 `time.time()` → `time.monotonic()`（NTP/PPS 跳变免疫；C++ 本就用 steady_clock）。
- 电池遥测看门狗（`battery_timeout_s`，默认 10s，**WARNING 级**——缺失遥测不触发 RTL）。
- 人工接管冷却（`manual_takeover_cooldown_s`，默认 10s）：操作手切 MANUAL 后不再被 0.5s 内拉回 GUIDED；failsafe RTL 不受冷却限制。
- set_mode/request_arm 加结果确认回调，被飞控拒绝时 ERROR 日志；WARNING 日志 5s 节流。
- 两个 C++ MPC 包 Q/R/Rd 数组长度启动校验；`require_fcu_state=false` 启动告警。
- Python 运动学 MPC：IPOPT 输出显式钳位（与 acados 对称）；代价函数文档与实现对齐（R 项为 u² 正则）；降级前瞻速度参数化 `kinematic.fallback_speed`；acados codegen 目录按 N/dt 隔离；测试 `sys.path` 不再依赖 CWD；IMU 注释对齐现实。
- 文档修正：`mpc_params_vrx.yaml` 标注 vrx_thrust_scale 模型失配；`usv_params*.yaml` 头注释指向 C++ 节点；maintainer 统一。
