usv_planning_cpp 代码入门讲解

为什么要分"纯算法库"和"ROS 节点"？

把数学算法（planning_lib）与 ROS 通信解耦，有两个好处：

1) 算法可以在没有 ROS 的环境下独立测试（如 gtest）；
2) 换一个通信框架（如 DDS 直接调用）时，算法代码完全不用改。

关键依赖：

  • Eigen3 — 线性代数库，替代 Python 的 numpy，用于向量/矩阵运算
  • rclcpp — ROS 2 的 C++ 客户端库
  • mavros_msgs / geographic_msgs — MAVROS 和地理坐标的消息类型

3. mission_bridge_node — 任务航点桥接

H
mission_bridge_node.hpp / .cpp
经纬度航点 → 本地 ENU 坐标转换

3.1 它解决什么问题？

地面站（QGroundControl）规划的航点是经纬度（如 lat=30.1234, lon=120.5678），但下游路径规划器需要的是本地平面坐标（以米为单位的 x, y）。mission_bridge_node 就是做这个坐标转换的"桥梁"。

3.3 关键代码解读

坐标转换公式

这是整个节点最核心的数学，把经纬度差转为 ENU 平面距离：

dE = (lon − lon₀) × (π/180) × R × cos(lat₀)
dN = (lat − lat₀) × (π/180) × R

其中 R = 6378137 m 是 WGS-84 地球半径，lat₀, lon₀ 是本地原点。对应的 C++ 代码：

mission_bridge_node.cpp 
// 经纬度 → ENU 平面坐标 (m)
double dE = (wp.y_long - lon0) * (M_PI / 180.0) * EARTH_RADIUS_M * cos_lat0;
double dN = (wp.x_lat  - lat0)  * (M_PI / 180.0) * EARTH_RADIUS_M;
💡 为什么乘 cos(lat₀)？

地球是球体，经线的间距从赤道到两极逐渐缩小。在纬度 lat₀ 处，1° 经度对应的实际距离 = 1° 纬度距离 × cos(lat₀)。这是平面近似（小范围适用）的标准做法。

双 QoS 订阅（latched + volatile）

// latched: 新订阅者能收到最后一条保留消息（适合"状态"类话题）
auto latched_qos = rclcpp::QoS(rclcpp::KeepLast(1))
    .reliable().transient_local();
// volatile: 普通订阅，只收新消息
auto volatile_qos = rclcpp::QoS(rclcpp::KeepLast(10)).reliable();

为什么同时用两种 QoS？因为不同版本的 MAVROS 可能用不同的 QoS 发布消息。双保险策略确保无论 MAVROS 端怎么配置，都能收到消息。

航点去重（签名机制）

// 计算"签名"：把航点列表的所有关键字段打包成一个 tuple vector
auto sig = waypoint_signature_(*msg);
// 如果签名和上次完全相同，就跳过——避免重复发布
if (last_signature_.has_value() && last_signature_.value() == sig) {
  return;
}

MAVROS 可能重复发布相同的航点列表，签名去重避免下游收到大量重复消息。

主动拉取（auto_pull）

如果 MAVROS 不主动推送航点列表，节点会通过 ROS 2 服务调用 /mavros/mission/pull 定时拉取：

if (auto_pull_) {

}

4. path_planner_node — 路径规划主节点

H
path_planner_node.hpp / .cpp
核心节点：航点 → 平滑路径 + 速度剖面

4.1 它解决什么问题？

拿到本地 ENU 航点后，path_planner_node 做三件事：

  1. 航点进度管理 — 判断船到达了哪个航点，该向哪个航点走
  2. 几何平滑 — 折线航点 → 圆弧倒角平滑路径（连续可导）
  3. 速度剖面 — 每个路径点该跑多快（弯道慢、直道快）

4.2 节点通信接口

方向话题消息类型说明
订阅 /mavros/local_position/odom Odometry 船的当前位置和速度
订阅 /usv/mission/waypoints_local Path 来自 mission_bridge 的本地航点
发布 /path/reference Path 平滑后的参考路径（位置+航向）
发布 /path/reference_profile Float64MultiArray 速度/曲率剖面 [v, κ, r, t]

void PathPlannerNode::publish_path_() {
  // 1) 更新航点进度
  wp_manager_.update_progress(x_, y_);

  // 2) 检查是否完成或航点不足
  if (wp_manager_.mission_complete()) { publish_empty_path_(); return; }
  if (wp_manager_.waypoints().size() < 2) { publish_empty_path_(); return; }

  // 3) 生成平滑路径 + 速度剖面
  auto result = generate_smooth_path_();

  // 4) 发布 NavPath（位置+航向）和 Profile（速度+曲率）
  path_pub_->publish(path_msg);
  profile_pub_->publish(build_profile_msg_(...));
}

4.4 里程计回调：四元数转偏航角

ROS 2 中姿态用四元数表示，但规划只需要偏航角 ψ：

// 从四元数 (w, x, y, z) 提取偏航角 psi
auto& q = msg->pose.pose.orientation;
double siny = 2.0 * (q.w * q.z + q.x * q.y);
double cosy = 1.0 - 2.0 * (q.y * q.y + q.z * q.z);
psi_ = std::atan2(siny, cosy);

5. waypoint_manager — 航点管理

H
waypoint_manager.hpp / .cpp
纯算法，无 ROS 依赖 — 航点列表与到达判定

5.1 核心数据结构

struct Waypoint {
  double x         = 0.0;   // 位置 x (m)
  double y         = 0.0;   // 位置 y (m)
  double radius    = 2.0;   // 到达判定半径 (m)
  double heading   = 0.0;   // 期望航向 (rad)
  double stay_time = 0.0;   // 停留时间 (s)
};

5.2 到达判定逻辑

当船距离当前航点的欧氏距离 < radius 时，认为"到达"，索引推进：

bool WaypointManager::update_progress(double x, double y) {
  const auto& wp = waypoints_[current_idx_];
  double dist = std::hypot(x - wp.x, y - wp.y);  // 欧氏距离
  if (dist < wp.radius) {                          // 进入到达半径
    current_idx_++;                                // 推进到下一航点
    if (current_idx_ >= waypoints_.size())
      mission_complete_ = true;                   // 所有航点走完
    return true;
  }
  return false;
}

6. trajectory_optimizer — 圆弧倒角平滑

H
trajectory_optimizer.hpp / .cpp
纯算法 — 折线航点 → 圆弧倒角平滑路径

这是整个包中数学最复杂的模块，也是最值得深入理解的部分。

6.1 为什么需要平滑？

航点之间是直线连接，在航点处航向突变（折线）。实际船不可能瞬间转向，需要把折角替换为圆弧过渡，使航向连续变化。这就是"圆弧倒角"（fillet）。

6.2 核心算法：fillet_path()

对每个中间航点，算法做以下步骤：

1
计算入/出方向单位向量：从前一航点到当前航点（入方向），从当前航点到下一航点（出方向）
2
计算有符号转角 δ：从入方向转到出方向的角度，左转正右转负
3
计算切线缩进 T：T = R × tan(|δ|/2)，其中 R 是最小转弯半径。T 不能超过航段长度的一半
4
生成直线段：从游标位置到入切点，按 resolution 采样
5
生成圆弧段：从入切点到出切点，用解析积分精确采样，曲率 κ = sign(δ) / r_eff

关键公式

T = min(R × tan(|δ|/2), ½ × min(L_in, L_out))

r_eff = T / tan(|δ|/2) （有效转弯半径，可能被裁剪）

κ = sign(δ) / r_eff （有符号曲率）

6.3 圆弧精确积分采样

这是最精妙的代码。不是简单地在圆弧上均匀取点，而是用解析积分保证采样点精确落在圆弧上：

// 每步 ds 的增量用解析公式，而非欧拉近似
if (std::abs(kappa) > 1e-9) {
  x += (std::sin(psi_next) - std::sin(psi)) / kappa;   // 精确圆弧增量
  y += (std::cos(psi) - std::cos(psi_next)) / kappa;
} else {
  x += ds * std::cos(psi);                              // 退化为直线
  y += ds * std::sin(psi);
}
💡 为什么不用简单的欧拉积分？

欧拉积分 x += ds * cos(psi) 在曲率大时会有漂移误差。解析公式从圆弧的精确解推导而来，无论步长多大都不会偏离圆弧，确保路径几何精度。

6.4 recompute_geometry() — 从点位重算几何

当最小曲率精修改动了点位后，需要从离散 (x, y) 重新计算航向和曲率。实现思路：

  • 用中心差分近似 dx/ds, dy/ds（端点用单侧差分）
  • psi = atan2(dy, dx)，然后 unwrap 保持连续
  • 曲率公式：κ = (dx·ddy − dy·ddx) / (dx² + dy²)^(3/2)

7. speed_profile — 时间最优速度剖面

H
speed_profile.hpp / .cpp
纯算法 — TOPP 时间最优速度剖面，O(N) 两遍扫描

7.1 问题定义

给定一条已知曲率的路径，在满足以下约束的条件下，让船尽快跑完全程：

约束公式物理含义
最大速度v ≤ u_max不要超速
最大转艏角速度|κ|·v ≤ r_max弯道限速
最大侧向加速度κ·v² ≤ a_lat_max别甩出去
最大纵向加速度v² ≤ v_prev² + 2·a_acc·ds加速不能太猛
最大纵向减速度v² ≤ v_next² + 2·a_dec·ds刹车不能太急

7.2 算法：确定性两遍扫描

这是经典的 TOPP（Time-Optimal Path Parameterization）的简化版本，时间复杂度 O(N)，非常快（<1ms）：

graph TD
  A["计算曲率限速包络 v_curve"] --> B["前向扫描：加速度约束"]
  B --> C["设置末端速度 v_end"]
  C --> D["后向扫描：减速度约束"]
  D --> E["梯形积分算时间 ts"]
  E --> F["rs = κ × v"]

第一步：曲率限速包络

在每个点，根据曲率计算速度上限：

for (int i = 0; i < n; ++i) {
  if (kappa_abs(i) > EPS) {
    double v_turn = r_max / kappa_abs(i);         // 转艏角速度约束
    double v_lat  = std::sqrt(a_lat_max / kappa_abs(i)); // 侧向加速度约束
    v_curve(i) = std::min({u_max, v_turn, v_lat}); // 取最严约束
  }
}

第二步：前向扫描 — 加速不能太快

for (int i = 1; i < n; ++i) {
  double ds = s(i) - s(i-1);
  // 从前一点的最大速度出发，本点最多能加速到多少？
  v(i) = std::min(v_curve(i),
                  std::sqrt(v(i-1) * v(i-1) + 2.0 * a_acc * ds));
}
v[i] = min(v_curve[i], √(v[i-1]² + 2·a_acc·Δs))

第三步：后向扫描 — 刹车不能太急

for (int i = n-2; i >= 0; --i) {
  double ds = s(i+1) - s(i);
  // 从后一点的速度倒推，本点速度不能超过多少才能刹得住？
  v(i) = std::min(v(i),
                  std::sqrt(v(i+1) * v(i+1) + 2.0 * a_dec * ds));
}
为什么前向+后向两遍扫描？

只做前向扫描的话，船会在弯道入口突然发现限速很低而来不及减速。后向扫描从终点往回推，提前识别出"必须减速"的区域，把减速点前移。两遍扫描的结果就是满足所有约束的最快速度剖面。

第四步：时间积分

// 梯形法则积分时间
for (int i = 1; i < n; ++i) {
  double ds    = s(i) - s(i-1);
  double v_avg = std::max(0.5 * (v(i-1) + v(i)), v_min);
  ts(i) = ts(i-1) + ds / v_avg;   // Δt = Δs / v_avg
}

设计模式总结

三层架构

这个包采用了清晰的三层架构：

  • 通信层（ROS 节点）：只负责消息收发和参数读取，不含任何数学
  • 协调层（path_planner_node 中的 generate_smooth_path_）：按顺序调用算法模块，编排数据流
  • 算法层（planning_lib 三个模块）：纯数学，无任何 ROS 依赖，可独立测试

这种分层让每一层都可以独立修改和测试，是 ROS 2 项目中推荐的组织方式。
