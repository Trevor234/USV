7. 两种接入方式
方案 A：直接把 ArduPilot 插件写进 WAM-V SDF/Xacro
这是最标准的 Gazebo-ArduPilot 方式。

你需要在 WAM-V 生成的 SDF 里加入类似：


<plugin
  filename="ArduPilotPlugin"
  name="ArduPilotPlugin">
  <fdm_addr>127.0.0.1</fdm_addr>
  <fdm_port_in>9002</fdm_port_in>
  <fdm_port_out>9003</fdm_port_out>
  <modelXYZToAirplaneXForwardZDown>0 0 0 3.141593 0 0</modelXYZToAirplaneXForwardZDown>
  <gazeboXYZToNED>0 0 0 3.141593 0 0</gazeboXYZToNED>

  <!-- 示例：ArduPilot servo output 映射到 Gazebo joint -->
  <control channel="0">
    <jointName>wamv/left_engine_propeller_joint</jointName>
    <useForce>1</useForce>
    <multiplier>1.0</multiplier>
    <offset>0</offset>
    <servo_min>1000</servo_min>
    <servo_max>2000</servo_max>
    <type>VELOCITY</type>
  </control>

  <control channel="1">
    <jointName>wamv/right_engine_propeller_joint</jointName>
    <useForce>1</useForce>
    <multiplier>1.0</multiplier>
    <offset>0</offset>
    <servo_min>1000</servo_min>
    <servo_max>2000</servo_max>
    <type>VELOCITY</type>
  </control>
</plugin>
上面 XML 是接入思路示例，具体标签名称要以 ardupilot_gazebo README 和示例模型为准。不同版本插件的 control 标签可能略有差异。

对你的项目来说，优先改：

vrx_urdf/wamv_gazebo/urdf/wamv_gazebo.urdf.xacro

或者在推进器布局里改：

vrx_urdf/wamv_gazebo/urdf/thruster_layouts/wamv_gazebo_thruster_config.xacro

方案 B：不直接改推进器插件，用 ROS 2/MAVROS 做桥接
这个更适合你的无人船项目已经有 ROS 2 控制链路的情况。

链路是：


ArduPilot SITL
   │ MAVLink
   ▼
MAVROS
   │ ROS 2 topic
   ▼
你的 ROS 2 控制/桥接节点
   │ 发布
   ▼
/wamv/thrusters/left/thrust
/wamv/thrusters/right/thrust
优点：

不深改 VRX 模型。
保留原来的 VRX thruster 插件。
方便把你的 MPC / planning / safety 接到 ROS 2 话题。
缺点：

Gazebo 的 IMU/GPS 等传感器要怎么反馈给 ArduPilot，需要你额外桥接。
不如 ardupilot_gazebo 插件原生闭环干净。
如果你的目标是 仿真飞控固件本身，推荐方案 A。

如果你的目标是 让 ROS 2 控制算法驱动 WAM-V，同时旁边跑 ArduPilot/MAVROS，可以先用方案 B。
