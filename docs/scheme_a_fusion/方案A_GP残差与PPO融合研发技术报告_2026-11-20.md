### 3.2 稀疏变分 GP、$Z_2$ 对称增强与 C++ 零外依赖引擎（WP4 + R2b + R3）

1. **模型形式（`gp-snapshot-v1`）**：
   - 在 `gp_model.py` 实现 3 个独立输出的 Titsias 稀疏变分 GP（`SparseChannelGP`，ARD-RBF 核，$M \in \{32, 64\}$ K-Means 诱导点）：输入标准化后执行 OOD 包络判据（输入边界超盒 + 至最近诱导点标准化欧氏距离 `ood_max_nearest_std_dist_ = 4.5`），输出经默认区间 `[-0.35, 0.35]` 限幅并在触发 OOD 时回退零残差，确保有界无发散。
2. **$Z_2$ 左右舷镜像对称数据增强（`R2b`）**：
   - 鉴于原训练数据左/右转工况分布存在偏差，`train_residual_gp.py` 新增 `augment_z2_symmetry(Z, Y)`：利用对称艇体 Fossen 动力学镜像关系 $(u, -v, -r, T_R, T_L) \mapsto (\Delta u, -\Delta v, -\Delta r)$ 将训练样本扩展为左右舷严格均衡的 2 倍样本（`n_train = 21788`，`--symmetrize-z2 --force-m 64`）。
3. **零外部 ML 依赖 C++ 推理与 Release 优化（`R3`）**：
   - `gp_predictor.hpp` / `gp_predictor.cpp` 仅依赖标准库直接解析 JSON 权重并校验二进制规范摘要。
   - `R3` 进一步在 `-O3` (`Release`) 构建下将内部向量改为固定容量栈数组 `std::array<double, kMaxInducing>`、以平方距离比较延迟 `std::sqrt`，并引入 `compute_variance=false` 分支跳过求解前不必要的 $2 \times M^2$ 矩阵乘，将单拍预测推进总耗时压至亚毫秒级。

### 3.3 `acados` 动态 NMPC 扩维与硬约束绝对优先（WP6–WP7）

在 `regenerate_acados_codegen.py` 中重写 `usv_dyn_nmpc` OCP 并重新生成 `acados_generated/dynamic/` 全套 C 代码：

- **阶段参数扩至 `np = 12`**：$p_k = [x_{\text{ref},k}(6),\; \delta\nu_k(3),\; q_{\pi,k}(2),\; \beta_{\pi,k}(1)]$。
- **离散动力学直接补偿**：4 子步 RK4 积分后，末态直接叠加 GP 预测的 0.2 s 离散速度残差增量 $\delta\nu_k = [\delta u_k, \delta v_k, \delta r_k]$：
  $$x_{k+1,\text{phys}} = \text{RK4}_4(x_{k,\text{phys}}, u_k) + [0, 0, 0, \delta u_k, \delta v_k, \delta r_k]^T,\quad \bar{T}_{k+1} = u_k$$
- **阶段代价扩至 `ny = 13`（`ny_0 = ny = 13`, `ny_e = 7`）**：在既有位置/单元圆航向/速度/控制/变化率残差基础上，追加末 2 维动作偏好残差 $\beta_{\pi,k}(u_k - q_{\pi,k})$，仅在首步 $k=0$ 注入 $\beta_{\pi,0} = \sqrt{2\lambda_\pi / \Delta t}$，在 `cost_scaling = dt` 与 `NONLINEAR_LS`（$\frac{1}{2}\|y\|^2$）形式下严格等价于：
  $$J_{\text{PPO}} = \lambda_\pi \|u_0 - q_\pi\|_2^2$$
- **执行器硬约束不让步**：`q_pi` 仅作为软代价项进入目标函数，始终受 `acados` 首步/全时域幅值硬边界 `[T_min, T_max]`（$\pm 25\text{ N}$）与变化率非线性不等式约束 `con_h_expr_0` / `con_h_expr`（$|\Delta T| \le \dot{T}_{\max}\Delta t = 16\text{ N/step}$）严格裁决；`acados_backend.hpp` 新增 5 参/6 参 `solve(..., stage_residuals, q_pi, lambda_pi)` 重载并保持原 2 参接口向后兼容。

## 4. `r1` 退化根因排查与 `r2` 关键修复（`R0`–`R6`）

`r1` 阶段出现的「GP-NMPC 精度反而不如 Nominal，且 P95 延迟近 10 ms」现象，经 `gp_regression_diagnosis.md` 的离线回放、ROS2 相位消融与 Oracle 物理上界对照，查明**三大独立根因**并在 `r2` 全部闭环解决：

1. **首要根因（`R2a`，`55f0cd9b`）：`SQP_RTI` 缺失 `accept_candidate()` 导致全冷启求解**
   - `usv_dyn_nmpc` 使用 `SQP_RTI`（每次 `solve()` 仅执行 1 步 QP 线性化），移位热启动 `(X_warm, U_warm)` 必须在候选就绪后由 `AcadosBackend::accept_candidate()` 提交。但在整个 `usv_research_safety_cpp` 中该方法此前有 **0 处调用**，导致每拍全部从零猜解强行求解。
   - **离线复现证据（`ep_59_test_yaw_damping_plus_15pct_right_turn`）**：开启热启动时 `oracle_stage` CTE 为 `0.03134 m`（相比 `nominal` `0.03791 m` 降低 **17.3%**）；一旦关闭热启动（`--no-warmstart 1`），`oracle_stage` 立刻恶化到 `0.18933 m`（劣于 `nominal` `0.11536 m`），精确复现了 `r1` ROS2 端 Oracle 反常劣于 Nominal 的现象。
   - **修复方案**：在 `solver_worker.cpp` 与 `p1_worker_engine.{hpp,cpp}` 中，仅当通过 `CandidateReady` 与资源边界检查时调用 `engine.accept_candidate()`。
2. **时序/状态传播与通信对齐（`R0`，`ac0213f3` + `8f57e999`）**：
   - 在 `regulator.cpp` 中增加 `declared_history_` 队列与 `receipts_.held_events()` 在 `snapshot_locked()` 统一合并，区分未闭环声明窗口与已确认执行历史；增加 `align_tick_to_plant_origin_` 与 `tick_phase_offset_ns_` 相位对齐参数与受控仿真的 `oracle_plant_file` 物理对照路径；将 `/p1/plant_command` 发布 QoS 深度由 `1` 改为 `16` 以匹配 plant 端订阅深度，消除 `+50ms` substep 抖动引发的偶发回执丢失。
   - 同时修复闭环评测指标口径（新增 `active_geometric_tracking` 排除末端 `shutdown` 降坡段的干扰，保留 `geometric_tracking` 全窗口作主对比口径，统一 `eval_fusion_arms.py` 与 `diagnose_gp_regression.py` 的 `ep_tag` 对齐逻辑）。
3. **推理编译与算子优化（`R3`，`ac0213f3`）**：
   - 切换为 `Release`（`-O3`）构建并关闭冻结传播中的不必要方差计算后，`gp_nmpc` 在 `12` 回合对比上的 E2E P50/P95 延迟从 `r1` 的 **`7.68 / 9.61 ms`** 骤降至 **`1.36 / 1.90 ms`**（提速 **5 倍**），`nominal` 从 `2.41 / 3.07 ms` 降至 `1.28 / 1.82 ms`。
4. **Linter 历史债务清零（`R6`，`f2d46c52`）**：
   - 修复 `usv_acados`（4 文件）与 `usv_nmpc`（9 文件含 `package.xml` schema URL）共计 16 处 `cpplint`/`uncrustify`/`xmllint` 问题。

## 7. 局限分析与后续建议

1. **GP vs GP+PPO 路线选择**：
   - 在当前冻结的 `v5/s4_dr` 策略与固定标量权重形式下，PPO 在直线 `straight` 段会引入微弱偏置（`0.0103` vs `0.0034 m`），仅在强变速 `speed_transition` 和 `heldout_combination` 有小幅帮助。若以**闭环几何追踪精度、简化系统依赖与稳定性**为先，建议后续主推**纯 `gp_nmpc_r2b`（$\lambda_\pi = 0$）**；若希望发挥 PPO 在大动态变速区的优势，应改为基于跟踪误差/速度变化率门控的条件式 $\lambda_\pi$ 调度，或基于 `"post_update"` 契约重训/微调 PPO 权重。
2. **航向/速度 RMSE 小幅上浮权衡**：
   - `oracle_nmpc`（Heading `0.2107` / Speed `0.1441`）与 `gp_nmpc_r2b`（Heading `0.2042` / Speed `0.1438`）均出现相对 Nominal（`0.1929` / `0.1363`）的小幅升高，反映消除动力学失配后控制器优先贴合参考几何路径、在转弯切入阶段伴随略大姿态角修正。
3. **ARM64 实机与实船闭环待补测**：
   - 在 `<USER>@<PI_DIRECT_IP>` 上板验证之前，需补齐 ARM64 原生 `Release` 编译、B2 实机 `shipboard_dry_run` 与 E2E 延迟摸底，并利用实船水试采集的合规回执日志验证真实海况水动力残差特性。
